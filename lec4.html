Intel x86 역사와 Architecture(아키텍처) 흐름

CISC(복잡 명령어 집합) vs RISC(축소 명령어 집합)

  • x86 : Intel 프로세서 계열의 ISA, laptop·desktop·server 시장을 지배
    • evolutionary design : 1978년 8086까지 backward compatible 유지 + 시간이 지나며 기능 추가
    • 모바일은 다른 생태계 → Qualcomm Snapdragon 등 ARM 계열 (Microsoft laptop에도 Snapdragon 탑재)
  • 서버/데스크톱과 모바일은 trade-off가 다름
    • 서버 : 가능한 한 빠르게 (performance)
    • 모바일 : 가능한 한 에너지 효율적으로 (power consumption, 배터리 수 시간 유지)
  • CISC (Complex Instruction Set Computer) : 형식이 제각각인 아주 많은 명령어
    • 명령어 길이 가변 → 1, 2, 3, 4 byte … 최대 16 byte 수준까지
    • 예 : 즉시값(immediate)을 메모리에 바로 저장하는 것을 명령어 하나로 표현 가능
    • 코드 줄 수는 적지만 하드웨어(decoder) 설계가 복잡
    • 실제 Linux 프로그램에서 쓰이는 명령어는 그중 일부뿐
  • RISC (Reduced Instruction Set Computer) : 단순하고 형식이 고정된 명령어
    • 필드 구성이 고정 → 앞쪽 몇 bit가 opcode(add, sub, mul …)를 나타내는 식으로 정형화
    • 같은 일을 하려면 명령어가 더 많이 필요 (예 : 즉시값을 먼저 register에 넣고 → 메모리에 store, 2단계)
    • 이해하기 쉬워서 컴퓨터구조 과목은 MIPS → 지금은 RISC-V 기반으로 가르침
  • CISC는 RISC 성능을 따라가기 어렵다고 여겨졌지만 Intel은 microarchitecture 기법(더 큰 cache 등)으로 따라잡음
    • 속도 면에서는 성공, 전력 소모 면에서는 덜 성공

Transistor(트랜지스터) 수와 Multi-core(멀티코어) 전환

  • 8086 (1978, 29K transistors, 5–10 MHz) : 첫 16-bit Intel 프로세서, IBM PC·DOS 기반, 1MB 주소 공간
  • 386 (1985, 275K, 16–33 MHz) : 첫 32-bit (IA32), flat addressing 추가 → Unix 구동 가능
  • Pentium 4E (2004, 125M, 2,800–3,800 MHz) : 첫 64-bit Intel 프로세서 (x86-64)
  • Core 2 (2006, 291M, 1,060–3,500 MHz) : 첫 multi-core Intel 프로세서
  • Core i7 (2008, 731M, 1,700–3,900 MHz) : 4 cores
  • 이름보다 트랜지스터 수에 주목 → 공정 기술 발전으로 같은 면적에 더 많은 트랜지스터 → 더 강력한 설계
    • 이후 Skylake (2015) 1.9B, Core i9 (2019) 3.5B
    • Moore's law : 트랜지스터 수(성능)가 주기적으로 두 배 → 예전 소프트웨어 엔지니어는 기다리기만 하면 single-thread 프로그램이 빨라졌음
  • clock speed 상승의 한계 : 내부 로직이 너무 복잡, 높은 clock을 위한 전력 소모, 신호 간섭
    • → clock 올리기를 포기하고 core 수를 늘리는 방향으로 전환 (dual, quad, 16 cores …)
    • 소프트웨어 입장에서는 골칫거리 → multi-thread 간 통신·동기화 overhead, straggler, 버그
  • 추가된 기능들
    • multimedia 연산 명령어 (Pentium/MMX), 조건부 연산을 효율적으로 하는 명령어
    • 32-bit → 64-bit 전환
    • 최근에는 남는 면적에 특정 workload용 가속 기능 (vector, matrix multiplication 등 AI 연산)
  • backward compatibility 가 중요한 이유 : 소프트웨어 전환은 하드웨어보다 훨씬 느림
    • 64-bit OS에서도 기존 32-bit application이 그대로 돌아야 함 (개발자가 사라져 고칠 사람이 없는 legacy도 존재)

Memory Hierarchy(메모리 계층)과 Register(레지스터)

  • memory hierarchy : 빠를수록 작고, 클수록 느림
    • register → cache → main memory → SSD/disk
    • 자주 쓰는 데이터일수록 위쪽(빠른 곳)에 두어야 함
  • cache : 한 socket 안의 여러 core가 공유, 최근 접근한 데이터가 자동으로 올라옴
    • 수업 예시 : cache 접근은 수 ~ 수십 cycle, cache miss로 memory까지 가면 수백 cycle
  • register : 가장 빠르고 가장 작은 "cache"로 볼 수 있음
    • 1 cycle 접근, x86-64 기준 8 byte짜리 16개 정도만 저장 가능
  • 2018년 Coffee Lake 예 : mobile Core i7 (2.2–3.2 GHz, 45 W), desktop Core i7 (35–95 W, integrated graphics), server Xeon E (multi-socket)
    • CPU 안에 graphics·media 처리 등 가속기 통합 추세
    • multi-socket : socket 간 통신은 QPI, 각 core는 local memory controller + remote memory 접근 가능

AMD와 x86-64의 탄생

  • AMD : 역사적으로 Intel보다 조금 느리지만 훨씬 저렴
    • DEC 등에서 설계자 영입 → Opteron (Pentium 4의 강력한 경쟁자)
    • ca. 2019 Ryzen부터 다시 경쟁력 회복, GPU에서도 NVIDIA 다음
  • Intel의 64-bit 역사
    • 2001 : IA32 → IA64 (Itanium) 로 급진적 전환 시도 → 완전히 다른 구조, IA32는 legacy로만 실행, 성능 실망
    • 2003 : AMD가 진화적 해법 x86-64 (AMD64) 발표
      • 32-bit register를 64-bit로 확장하고, 32-bit 프로그램은 64-bit register의 하위 절반만 쓰면 되게 함 → 프로그램 변경 없이 호환
    • 2004 : Intel이 EM64T 발표 → x86-64와 거의 동일
    • 현재는 저가형 제외 모든 x86이 x86-64 지원 (32-bit 모드 코드도 여전히 많음)
  • 수업 범위 : x86-64만 다룸 (gcc hello.c = 기본 64-bit, gcc -m64)

C, Assembly(어셈블리), Machine Code(머신 코드)

ISA(명령어 집합 구조) vs Microarchitecture(마이크로아키텍처)

  • machine code : 프로세서가 실행하는 byte 수준 프로그램
  • assembly code : machine code의 텍스트 표현 (human-readable), machine code와 거의 1:1 대응
  • ISA (Instruction Set Architecture) : 올바른 assembly/machine code를 쓰기 위해 알아야 하는 프로세서 설계 부분
    • 예 : 명령어 집합 명세, register
    • 하드웨어에 대한 abstraction → 명령어가 무슨 의미이고 실행하면 어떤 효과가 있는지만 정의
  • microarchitecture : ISA의 실제 구현
    • 예 : cache 크기, core 주파수, register가 칩의 어디에 있는지
    • 프로그래머에게 숨겨짐 → 몰라도 되지만 ISA 명세는 반드시 이해해야 함
  • ISA 예
    • Intel : x86, IA32, Itanium, x86-64 : CISC 계열 (Itanium은 별개 구조)
    • ARM : 거의 모든 휴대폰
    • RISC-V : 새로운 open-source ISA
  • compiler는 최근 GPU 활용 때문에 매우 중요한 연구 분야

Assembly(어셈블리) 프로그래머가 보는 상태

  • C에서는 안 보이던 programmer-visible state
  • PC (program counter) : 다음 실행할 명령어의 주소, IA32는 %eip, x86-64는 %rip
  • Register file : 많이 쓰는 프로그램 데이터 저장
  • Condition codes : 가장 최근 산술 연산의 상태 정보 → 조건 분기(if/else, loop)에 사용
  • Memory : byte-addressable 배열, code·user data·(일부) OS data·stack 저장
  • 이름 규칙 : R 접두 = 64-bit, E 접두 = 32-bit
  • 흐름 : 프로그램이 memory에 올라감 → CPU가 명령어 fetch → memory에서 data 읽기 → 연산 → write back

C → Executable(실행 파일)

  • 명령 : gcc -Og p1.c p2.c -o p
    • -Og : 기본적인 최적화만 (디버깅·읽기 쉬운 assembly)
  • ① Compile : compiler (gcc -S), p1.c p2.c → p1.s p2.s (text → text)
  • ② Assemble : assembler (gcc 또는 as), p1.s p2.s → p1.o p2.o (text → binary)
  • ③ Link : linker (gcc 또는 ld), p1.o p2.o + static library (*.a) → p (binary → 실행 파일)
  • assembler : .s → .o, 각 명령어의 binary encoding
    • 거의 완성된 실행 코드 image, 단 다른 파일 코드와의 연결(linkage)이 빠져 있음
  • linker : 파일 간 참조를 해결, static run-time library(malloc, printf 코드 등)와 결합
    • 일부 library는 dynamically linked → 프로그램 실행 시작 시 linking

sumstore 예제

  • gcc -Og -S sum.c → sum.s 생성
    • 같은 코드라도 기계·GCC 버전·설정에 따라 결과가 크게 다름
long plus(long x, long y);
void sumstore(long x, long y, long *dest) {
    long t = plus(x, y);
    *dest = t;
    return;
}
sumstore:
    pushq   %rbx          # rbx 값을 stack에 저장
    movq    %rdx, %rbx    # dest(3번째 인자)를 rbx로
    call    plus          # t = plus(x, y), 결과는 %rax
    movq    %rax, (%rbx)  # *dest = t
    popq    %rbx          # rbx 복원
    ret
  • 각 함수는 이름(label)으로 시작 → 그 아래가 해당 함수의 assembly
  • 모든 줄을 지금 이해할 필요는 없음 → C의 함수 호출은 call, 대입 *dest = t는 register → memory 이동으로 바뀐다는 것이 핵심

Assembly(어셈블리)의 특징

  • data type
    • 정수 : 1, 2, 4, 8 byte → 데이터 값과 주소(type 없는 pointer)를 구분하지 않음
    • 부동소수점 : 4, 8, 10 byte (별도 register 사용)
    • code : 명령어를 encoding한 byte 열
    • aggregate type 없음 → array, struct는 memory에 연속 할당된 byte일 뿐 (주소를 직접 계산해서 접근)
  • operation
    • register 또는 memory 데이터에 대한 산술 연산 (memory operand 산술은 x86 특유, RISC는 일반적으로 불가)
    • register ↔ memory 데이터 전송 : load (memory → register), store (register → memory)
    • 제어 이동 : procedure로의 무조건 jump, conditional branch (if/else 구현)

Object Code(목적 코드)와 Disassembly(역어셈블)

  • sumstore의 object code : 주소 0x400595부터 총 14 byte, 명령어 하나는 1, 3, 5 byte
    • hex 나열만 봐서는 어떤 명령어인지 알기 어려움 → disassembler 필요
0000000000400595 <sumstore>:
  400595: 53                push   %rbx
  400596: 48 89 d3          mov    %rdx,%rbx
  400599: e8 f2 ff ff ff    callq  400590 <plus>
  40059e: 48 89 03          mov    %rax,(%rbx)
  4005a1: 5b                pop    %rbx
  4005a2: c3                retq
  • *dest = t; → movq %rax, (%rbx) → 0x40059e: 48 89 03
    • t는 register %rax, dest는 register %rbx, *dest는 memory M[%rbx]
    • 8 byte 값을 memory로 이동 → x86-64 용어로 quadword
    • 괄호 ( ) = register 값을 주소로 보고 그 memory 위치에 접근
  • disassembler : objdump -d sum
    • 명령어 bit pattern을 분석해 대략적인 assembly 재구성, 실행 파일(a.out)과 .o 모두 가능
    • source 없이 object만 있을 때 분석(reverse engineering) 수단
  • gdb : gdb sum → disassemble sumstore, x/14xb sumstore (sumstore부터 14 byte를 hex로)
  • 실행 코드로 해석 가능한 것은 무엇이든 disassemble 가능 (예 : objdump -d WINWORD.EXE)

손계산 1 : sumstore byte 수와 call 대상 주소

  • 0x400595 : 53 (1 byte) → push %rbx
  • 0x400596 : 48 89 d3 (3 byte) → mov %rdx,%rbx
  • 0x400599 : e8 f2 ff ff ff (5 byte) → callq plus
  • 0x40059e : 48 89 03 (3 byte) → mov %rax,(%rbx)
  • 0x4005a1 : 5b (1 byte) → pop %rbx
  • 0x4005a2 : c3 (1 byte) → retq
  • 합계 byte → 슬라이드의 "Total of 14 bytes"와 일치
  • 각 주소 = 이전 주소 + 이전 명령어 길이 (예 : )
  • (보충) call의 피연산자 f2 ff ff ff는 little-endian 32-bit 상대 offset
    • → 기준은 다음 명령어 주소
    • → <plus> 주소와 일치

Register(레지스터), Operand(피연산자), mov

x86-64 정수 Register(레지스터)

  • 16개 64-bit 정수 register : %rax %rbx %rcx %rdx %rsi %rdi %rsp %rbp %r8–%r15
  • 하위 4 byte (그리고 하위 2 byte, 1 byte)도 이름으로 참조 가능
    • %rax 하위 4 byte = %eax, %r8 하위 4 byte = %r8d
    • register를 따로 두지 않고 하나의 register를 크기별 이름으로 나눠 씀 → 효율적
  • 64-bit → 하위 32 / 16 / 8-bit, 괄호 안은 IA32 시절 이름의 유래
    • %rax → %eax / %ax / %al (상위 byte %ah) (accumulate)
    • %rcx → %ecx / %cx / %cl (%ch) (counter)
    • %rdx → %edx / %dx / %dl (%dh) (data)
    • %rbx → %ebx / %bx / %bl (%bh) (base)
    • %rsi → %esi / %si (source index)
    • %rdi → %edi / %di (destination index)
    • %rsp → %esp / %sp (stack pointer)
    • %rbp → %ebp / %bp (base pointer)
    • %r8 – %r15 → %r8d – %r15d (64-bit에서 추가, 8개 → 16개)

IA32 Register(레지스터)의 역사

  • IA32 : register 8개뿐 (%eax %ecx %edx %ebx %esi %edi %esp %ebp)
    • 16-bit virtual register(%ax 등)는 backward compatibility용
    • 이름은 원래 각 register의 특수 역할(accumulate, counter …)에서 왔지만 현재는 대부분 obsolete → 6개는 general purpose
    • 각 register에 역할을 고정하는 것이 비효율적이라는 것이 드러남
  • %esp / %rsp : stack pointer, 지금도 특수 용도
    • 함수 호출 전 context를 stack에 저장하고 복귀 후 꺼내야 함 → stack pointer가 핵심
    • 직접 건드리면 함수 stack이 망가짐 → 사실상 하드웨어·호출 규약이 관리
  • %ebp / %rbp : base pointer, 64-bit에서는 general purpose로 돌아감
    • 32-bit : 인자를 stack(memory)으로 전달 → 중첩 호출 시 현재 함수 frame 위치를 추적하려고 base pointer 사용
    • 64-bit : 인자를 register로 전달 → memory stack을 볼 필요가 줄어 base pointer 불필요

함수 인자 Register(레지스터)

  • 인자 전달 규약 (수업 설명)
    • 1번째 인자 → %rdi, 2번째 → %rsi, 3번째 → %rdx
    • return 값 → %rax
    • (보충) 4~6번째는 %rcx %r8 %r9
  • 함수를 호출하는 쪽은 인자를 이 register에 넣어야 함 → 호출 전에 거기 있던 값은 다른 곳에 안전하게 저장해 두어야 함

movq와 Operand(피연산자) 종류

  • movq src, dest : src의 데이터를 dest로 이동 (q = quadword, 8 byte)
    • operand 순서 : source가 앞, destination이 뒤 (AT&T 문법)
      ISA가 명세하는 동작이고 실제 구현 방식은 microarchitecture에 숨겨짐
    • → Source의 값을 Destination에 복사하는 명령어
  • Immediate ($0x400, $-533) : 상수, C 상수와 같지만 $ 접두, 1·2·4 byte로 encoding
    • → 숫자 자체 / 상수
  • Register (%rax, %r13) : 16개 정수 register 중 하나, %rsp는 특수 용도 예약
    • → CPU 내부 저장 공간
  • Memory ((%rax)) : register가 가리키는 주소의 연속 8 byte, 다양한 address mode
    • → 메모리 저장 값. (%rax) ⇒ %rax 에 메모리의 주소를 저장, 그 값을 가져옴.
  • immediate는 encoding 크기에 범위가 제한됨 → 아주 큰 값/아주 작은 음수는 먼저 register에 넣은 뒤 이동

movq Operand(피연산자) 조합

  • Imm → Reg : movq $0x4, %rax ↔ temp = 0x4;
    • 숫자 4를 %rax 에 저장함.
  • Imm → Mem : movq $-147, (%rax) ↔ *p = -147;
    • 숫자 4를 (%rax) - %rax가 가르키는 memory 에 저장
  • Reg → Reg : movq %rax, %rdx ↔ temp2 = temp1;
    • Reg에 저장되어있던 값을, 복사해감
  • Reg → Mem : movq %rax, (%rdx) ↔ *p = temp;
    • (%red)가 가리키는 메모리 주소에, %rax의 값을 저장함.
  • Mem → Reg : movq (%rax), %rdx ↔ temp = *p;
    • %rax가 가리키는 메모리에 저장된 값을 %rdx에 복사
  • (슬라이드의 movq $rax,...는 %rax 오타)
  • destination이 immediate인 경우는 없음 → 상수에 값을 넣는 것은 말이 안 됨
  • memory → memory 이동은 명령어 하나로 불가
    • 반드시 memory → register (load), register → memory (store) 두 단계
    • 이유 : memory는 CPU와 연결된 별도 하드웨어 → CPU가 읽어 와야 함
    • memory 블록 복사를 CPU 없이 하는 것은 DMA (direct memory access) 엔진의 역할

Memory Addressing Mode(메모리 주소 지정 방식)

단순 Addressing Mode(주소 지정 방식)

  • Normal (R) :
    • register R이 memory 주소를 가짐 → C의 pointer dereference
    • movq (%rcx), %rax
  • Displacement D(R) :
    • register R = 시작 주소, 상수 D = offset
    • struct의 시작 주소에 각 member의 offset을 더해 접근하는 경우에 자연스러움
    • movq 8(%rbp), %rdx
    • 배열이나 구조체에서 원하는 데이터에 접근하기 위해서 씀.
      long은 여기서 8바이트이기 때문에 원소마다 주소가 8씩 증가.

손계산 2 : swap 추적

void swap(long *xp, long *yp) {
    long t0 = *xp;
    long t1 = *yp;
    *xp = t1;
    *yp = t0;
}
swap:
    movq    (%rdi), %rax    # t0 = *xp
    movq    (%rsi), %rdx    # t1 = *yp
    movq    %rdx, (%rdi)    # *xp = t1
    movq    %rax, (%rsi)    # *yp = t0
    ret
  • register 대응 : %rdi=xp (1번째 인자), %rsi=yp (2번째 인자), %rax=t0, %rdx=t1
  • 초기 상태 (슬라이드 값) : %rdi = 0x108, %rsi = 0x120, memory M[0x108] = 0x232, M[0x120] = 0x873
  • 각 단계 후 %rax / %rdx / M[0x108] / M[0x120]
    • 시작 : ? / ? / 0x232 / 0x873
    • ① movq (%rdi), %rax : 0x232 / ? / 0x232 / 0x873
    • ② movq (%rsi), %rdx : 0x232 / 0x873 / 0x232 / 0x873
    • ③ movq %rdx, (%rdi) : 0x232 / 0x873 / 0x873 / 0x873
    • ④ movq %rax, (%rsi) : 0x232 / 0x873 / 0x873 / 0x232
  • ③ 직후에는 두 칸이 모두 0x873 → 원래 값 0x232가 %rax에 보관돼 있어서 ④에서 복구 가능
  • memory 두 값을 직접 맞바꾸는 명령어가 없으므로 register 두 개를 임시 저장소로 사용 (load 2번 + store 2번)

일반형 D(Rb,Ri,S)

  • D(Rb,Ri,S) :
    • D : 상수 displacement (offset), 1, 2, 4 byte
      Rb : base register, 16개 정수 register 아무거나
      Ri : index register, %rsp 제외 아무거나
      S : scale, 1, 2, 4, 8
  • S가 1, 2, 4, 8인 이유 : 배열 원소 크기 → char 1, short 2, int 4, long/pointer 8 byte
    • Rb = 배열 시작 주소, Ri = 인덱스, S = 원소 크기 → &a[i] =
      D까지 더하면 struct 배열의 특정 field 접근 등도 한 번에 표현
  • 특수 경우 (생략된 필드는 0으로 취급, S 생략 시 1)
    • (Rb,Ri) :
      D(Rb,Ri) :
      (Rb,Ri,S) :
      D(,Ri,S) : base 없음 →

손계산 3 : 주소 계산

  • %rdx = 0xf000, %rcx = 0x0100
  • 0x8(%rdx) : 0xf000 + 0x8 → 0xf008
  • (%rdx,%rcx) : 0xf000 + 0x100 → 0xf100
  • (%rdx,%rcx,4) : 0xf000 + 4 × 0x100 = 0xf000 + 0x400 → 0xf400
  • 0x80(,%rdx,2) : 2 × 0xf000 + 0x80 = 0x1e000 + 0x80 → 0x1e080
  • 마지막 식 : base 생략 → base = 0, index %rdx에 scale 2
    • (0xf × 2 = 0x1e)
  • 이 표의 값은 "주소"까지만 → mov에 쓰이면 그 주소의 memory를 실제로 읽음

lea(Load Effective Address)와 산술 연산

leaq : 주소 계산 명령어

  • leaq src, dst : src(address mode 표현식)가 나타내는 주소 자체를 dst에 저장
    • load effective address
      memory에 접근하지 않음 → 메모리 주소만 복사
  • mov 6(%rbx,%rdi,8), %ax ↔ ax = *(rbx + rdi*8 + 6) : memory 읽기
    add 6(%rbx,%rdi,8), %ax ↔ ax += *(rbx + rdi*8 + 6) : memory 읽기
    xor %ax, 6(%rbx,%rdi,8) ↔ *(rbx + rdi*8 + 6) ^= ax : memory 읽기 + 쓰기
    lea 6(%rbx,%rdi,8), %rax ↔ rax = rbx + rdi*8 + 6 : memory 접근 없음
  • 대부분의 명령어에서 memory operand는 memory에 접근 → LEA만 예외

lea를 쓰는 이유

  • CPU 설계자의 의도 : object를 가리키는 pointer 계산
    • 예 : 배열 원소 하나의 주소만 다른 함수에 넘길 때 p = &x[i];
    • lea (%rbx,%rdi,8), %rax ↔ rax = &rbx[rdi]
  • compiler 작성자는 일반 산술에도 즐겨 사용
    • 꼴 ()을 명령어 하나로 계산
      lea (%rbx,%rbx,2), %rax ↔ rax = rbx * 3 → mul + add 조합 없이 한 번에
      x86에서 몇 안 되는 3-operand 명령어 (base, index → 별도 dst)
      condition code를 건드리지 않음 (뒤에서 다시 다룸)
  • 비유 : 머신러닝 하드웨어가 multiply-add를 하나의 명령어로 합쳐 가속하는 것과 같은 발상

손계산 4 : m12 (x × 12)

long m12(long x) {
    return x * 12;
}
leaq    (%rdi,%rdi,2), %rax   # t <- x + x*2 = 3x
salq    $2, %rax              # return t << 2 = 4t
  • 대입
    • leaq :
      salq $2 :
  • 곱셈 명령어 없이 lea + shift로 곱하기 12 구현 ()

2-Operand(피연산자 2개) 산술 명령어

  • addq src, dst : dst = dst + src
    subq src, dst : dst = dst − src (순서 주의 : dst에서 src를 뺌)
    imulq src, dst : dst = dst × src
    salq src, dst : dst = dst << src (shlq와 같음)
    sarq src, dst : dst = dst >> src (arithmetic, sign bit 복제)
    shrq src, dst : dst = dst >> src (logical, 0 채움)
    xorq src, dst : dst = dst ^ src
    andq src, dst : dst = dst & src
    orq src, dst : dst = dst | src
  • 인자 순서 주의 : 명령어마다 어느 쪽이 source/destination인지 확인해야 함
  • signed / unsigned 구분 없음 : two's complement 덧셈·뺄셈은 bit 수준 동작이 동일하기 때문 (Lab 2의 TAdd = UAdd와 같은 이야기)
  • left shift는 signed/unsigned 상관없이 오른쪽에 0을 채움
  • right shift는 프로그래머가 선택해야 함
    • sarq : 왼쪽을 sign bit로 채움 → 음수의 부호 유지
      shrq : 왼쪽을 0으로 채움

1-Operand(피연산자 1개) 산술 명령어

  • incq dst : dst = dst + 1
    decq dst : dst = dst − 1
    negq dst : dst = −dst
    notq dst : dst = ~dst
    • inc/dec는 loop counter 증감에 유용, 나머지는 책 참고

명령어 Suffix(접미사)

  • 대부분의 x86 명령어는 suffix 있이/없이 모두 표기 가능 : imul %rcx, %rax = imulq %rcx, %rax
  • suffix = 연산 크기
    • b = byte (1), w = short (2), l = int (4), q = long (8)
    • suffix가 있으면 register 이름과 크기가 일치해야 함
  • compiler 출력(gcc -S)은 보통 suffix 있음
  • disassembly(objdump -d, gdb disas)는 보통 생략, Intel 매뉴얼은 항상 생략

손계산 5 : arith 추적

long arith(long x, long y, long z) {
    long t1 = x + y;
    long t2 = z + t1;
    long t3 = x + 4;
    long t4 = y * 48;
    long t5 = t3 + t4;
    long rval = t2 * t5;
    return rval;
}
arith:
    leaq    (%rdi,%rsi), %rax     # t1 = x + y
    addq    %rdx, %rax            # t2 = z + t1
    leaq    (%rsi,%rsi,2), %rdx   # 3y
    salq    $4, %rdx              # t4 = 3y << 4 = 48y
    leaq    4(%rdi,%rdx), %rcx    # t5 = x + t4 + 4
    imulq   %rcx, %rax            # rval = t2 * t5
    ret
  • register : %rdi=x, %rsi=y, %rdx=z → 나중에 t4로 재사용, %rax=t1·t2·rval, %rcx=t5
  • 대입
  • 각 명령어 후 %rax / %rdx / %rcx
    • 시작 : ? / 3 (z) / ?
      leaq (%rdi,%rsi), %rax : 1 + 2 = 3 / 3 / ?
      addq %rdx, %rax : 3 + 3 = 6 / 3 / ?
      leaq (%rsi,%rsi,2), %rdx : 6 / 2 + 2×2 = 6 / ?
      salq $4, %rdx : 6 / 6 × 16 = 96 / ?
      leaq 4(%rdi,%rdx), %rcx : 6 / 96 / 1 + 96 + 4 = 101
      imulq %rcx, %rax : 6 × 101 = 606 / 96 / 101
  • C로 직접 계산 : → 일치
  • 관찰 포인트
    • ① 인자 3개가 %rdi %rsi %rdx로 전달됨
      ② y*48을 으로 분해 → lea(3y) + shift(×16)
      ③ t3 = x + 4는 별도 명령어 없이 lea의 displacement 4로 흡수
      ④ C에는 곱셈이 2번이지만 assembly에는 imulq 1번뿐
      ⑤ C 문장 순서와 assembly 순서가 꼭 같지는 않음 (compiler가 재배치)

시험 포인트

  • ISA = 프로그래머가 알아야 하는 명세(명령어, register), microarchitecture = 구현(cache 크기, 주파수)
  • CISC(x86) : 가변 길이·다양한 명령어 / RISC(ARM, RISC-V) : 고정 형식·단순 명령어
  • clock 상승 한계 → multi-core로 전환, backward compatibility가 x86 진화의 핵심
  • x86-64는 AMD가 먼저 (AMD64), Intel의 IA64(Itanium)는 실패 → EM64T
  • C → (compiler) .s → (assembler) .o → (linker + library) 실행 파일
  • assembly에는 array/struct 같은 aggregate type이 없음 → 연속된 byte + 주소 계산
  • programmer-visible state : PC(%rip), register, condition codes, memory
  • %rsp는 stack pointer로 특수 용도, %rbp는 64-bit에서 general purpose
  • 인자 순서 : %rdi, %rsi, %rdx, 반환값 %rax
  • mov operand : Imm/Reg/Mem 중 dest에 Imm 불가, memory→memory 한 명령어로 불가
  • D(Rb,Ri,S) = Mem[Rb + S×Ri + D], S ∈ {1,2,4,8} (자료형 크기), Ri에 %rsp 불가
  • lea는 주소만 계산하고 memory에 접근하지 않음, condition code 불변, x + k·y + d 산술에 활용
  • AT&T 문법은 src, dst 순서 → subq src, dst는 dst − src
  • sar = arithmetic(sign 복제), shr = logical(0 채움), add/sub는 signed/unsigned 구분 없음
  • suffix b/w/l/q = 1/2/4/8 byte

연습문제

문제 1

  • %rax = 0x100, %rcx = 0x3 일 때 다음 표현식이 나타내는 주소를 구하라.
    • ① 4(%rax) ② (%rax,%rcx,8) ③ 0x10(%rax,%rcx,8) ④ (,%rcx,4)
답
    • ① 0x100 + 4 = 0x104
    • ② 0x100 + 8 × 3 = 0x100 + 0x18 = 0x118
    • ③ 0x118 + 0x10 = 0x128
    • ④ base 없음 → 4 × 3 = 0xc

문제 2

  • 다음 중 x86-64에서 유효하지 않은 명령어를 고르고 이유를 써라.
    • ① movq $5, %rax ② movq (%rax), (%rbx) ③ movq %rax, $5 ④ movq %rdx, 8(%rsp) ⑤ movq (%rax,%rsp,4), %rbx
답
    • ② memory → memory 이동은 명령어 하나로 불가 → register를 거쳐 두 번에 나눠야 함
    • ③ destination이 immediate일 수 없음
    • ⑤ index register Ri로 %rsp는 사용 불가
    • ① ④는 유효 (Imm→Reg, Reg→Mem)

문제 3

  • %rbx = 0x1000, %rdi = 3이고 주소 0x101e에 저장된 8 byte 값이 42일 때, 다음 두 명령어 실행 후 %rax 값을 각각 구하라.
    • ① movq 6(%rbx,%rdi,8), %rax ② leaq 6(%rbx,%rdi,8), %rax
답
    • 주소 = 0x1000 + 3 × 8 + 6 = 0x1000 + 0x18 + 0x6 = 0x101e
    • ① mov는 그 주소의 memory를 읽음 → %rax = 42
    • ② lea는 주소 자체만 저장 → %rax = 0x101e

문제 4

  • 다음 assembly가 계산하는 C 함수를 쓰고, 일 때 반환값을 구하라.
leaq    (%rdi,%rdi,4), %rax
salq    $2, %rax
ret
답
    • leaq : x + 4x = 5x, salq $2 : 5x × 4 = 20x
    • long f(long x) { return x * 20; }
    • x = 7 → 5 × 7 = 35 → 35 × 4 = 140

문제 5

  • 본문의 arith assembly를 으로 추적해 각 명령어 직후 %rax, %rdx, %rcx 값과 최종 반환값을 구하라.
답
    • leaq (%rdi,%rsi), %rax → %rax = 3
    • addq %rdx, %rax → %rax = 3 + 3 = 6
    • leaq (%rsi,%rsi,2), %rdx → %rdx = 1 + 2 = 3
    • salq $4, %rdx → %rdx = 48
    • leaq 4(%rdi,%rdx), %rcx → %rcx = 2 + 48 + 4 = 54
    • imulq %rcx, %rax → %rax = 6 × 54 = 324
    • C 검산 : t2 = 3 + (2+1) = 6, t5 = (2+4) + 48 = 54, 6 × 54 = 324

문제 6

  • %rax = -8 (64-bit)일 때 sarq $1, %rax와 shrq $1, %rax의 결과를 각각 구하라 (shr 결과는 hex로).
답
    • −8 = 0xFFFFFFFFFFFFFFF8
    • sarq : sign bit(1) 복제 → 0xFFFFFFFFFFFFFFFC = −4
    • shrq : 왼쪽에 0 → 0x7FFFFFFFFFFFFFFC (큰 양수)
