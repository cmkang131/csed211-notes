추상화 수준 (Level of Abstraction)

같은 프로세서, 보는 사람마다 다른 모습

  • 예 : 2nd Generation Xeon Phi
  • semiconductor engineer : transistor 수, core 수, 메모리 대역폭 등 hardware 사양을 봄
    • 관심사 : 물리적 구현의 모든 세부
  • high-level computer architect : register → 연산 유닛 → memory로 이어지는 블록 다이어그램을 봄
    • 관심사 : 어디에 있는지보다 어떻게 동작하는지 (instruction이 register의 data로 계산하고 결과를 memory에 씀)
  • system software programmer : machine code / assembly code를 봄
    • 관심사 : 무엇을 계산할 수 있는가 (data가 내부에서 어떻게 움직이는지는 관심 밖)
  • Xeon Phi 사양 (semiconductor engineer 관점)
    • 8 billion 개 이상의 transistor, self-hosted manycore processor
    • 최대 72 cores, core당 4 SMT threads, 32개의 512-bit vector register
    • 최대 384GB DDR4-2400 main memory → 최대 115GB/s
    • 최대 16GB on-package MCDRAM (3D stacked) → 최대 400GB/s
  • programmer에게 이 사양은 직접적인 정보가 아님 → 이 과목에서 모든 세부를 알 필요는 없음

손계산 1 : Xeon Phi 사양 읽기 (보충)

  • 동시에 돌 수 있는 hardware thread 수 : = 288
  • vector register 하나에 들어가는 32-bit int 개수 : = 16
  • vector register 32개의 총 크기 : bytes = 2048 B = 2 KB
  • MCDRAM vs DDR4 대역폭 비 : = 약 3.5배
  • ⇒ 가까이 붙은(on-package) 작은 메모리가 훨씬 빠름 → 뒤에서 배울 memory hierarchy의 예고

System Software Programmer(시스템 소프트웨어 프로그래머)의 관점 : 코드

  • 슬라이드 예시 : 배열 100개 원소의 합을 구하는 loop (machine code ↔ assembly)
x9A00  CONST   R5, #0
x9200  CONST   R1, array
xD320  HICONST R1, array
x9464  CONST   R2, sum
xD520  HICONST R2, sum
x6640  LDR     R3, R1, #0
x6880  LDR     R4, R2, #0
x18C4  ADD     R4, R3, R4
x7880  STR     R4, R2, #0
x1261  ADD     R1, R1, #1
x1BA1  ADD     R5, R5, #1
x2B64  CMPI    R5, #100
x03F8  BRn     array_sum_loop
  • 왼쪽 hex = machine code, 오른쪽 = assembly code (사람이 읽는 텍스트 표현)
  • ADD R4, R3, R4 한 줄 : "R3와 R4를 더해 R4에 저장" → 무엇을 하는지만 보여주고 data가 내부에서 어떻게 움직이는지는 숨김
    • 실제로는 내부의 여러 단계를 거칠 수 있지만 programmer의 관심은 이 high-level specification

손계산 2 : Machine Code(머신 코드) 한 줄 해독 (보충)

  • 슬라이드 ISA는 교육용 LC-4 형식으로 보임 (16-bit instruction, 앞 4 bit = opcode)
  • x18C4 = 0001 1000 1100 0100 → ADD R4, R3, R4
    • 0001(ADD) · 100(Rd=R4) · 011(Rs=R3) · 000 · 100(Rt=R4)
  • x6640 = 0110 0110 0100 0000 → LDR R3, R1, #0
    • 0110(LDR) · 011(Rd=R3) · 001(Rs=R1) · 000000(offset 0)
  • ⇒ machine code = bit로 인코딩된 instruction, assembly = 그것의 텍스트 표현

Abstraction(추상화)의 정의와 프로그램 코드의 계층

  • Abstraction : 하위 수준의 구현 세부를 숨기고 interface만 제공 → complexity를 다루게 해줌
  • user는 "how"가 아니라 "what"에 관심
    • hardware가 어떻게 만들어졌는지, data가 datapath에서 어떻게 움직이는지는 숨겨짐
  • 프로그램 코드의 세 계층
    • High-level language : problem domain에 가까움 → productivity, portability
    • Assembly language : instruction의 textual representation
    • Hardware representation : binary digits (bits) → encoded instructions and data
  • high-level 프로그램도 결국 하위 수준으로 번역되어 hardware 위에서 실행됨 → 그래서 abstraction이 중요
  • 이 과목의 관심 = 주로 assembly와 그 아래 수준
