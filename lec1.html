1이 과목이 다루는 것

과목 목표

  • CSED211 (Introduction to Computer Software Systems): 저수준(low-level) 소프트웨어 시스템 입문

슬라이드의 네 가지 목표

  1. Computer organization의 기본 개념 → 컴퓨터 하드웨어 구조(architecture)에 매우 가까움
  2. Software가 hardware와 어떻게 함께 동작하는가 → 주어진 hardware 위에서 software를 실행하는 인터페이스
  3. Intel assembly language + 실습 → 하드웨어 위에서 프로그램을 직접 기술하는 수준
  4. System programming으로 시스템 구성요소를 저수준에서 관리하는 개념
⇒ 네 가지 모두 "low level"을 가리킨다.
  • 교재: CS:APP (Computer Systems: A Programmer's Perspective, Bryant & O'Hallaron, 3rd ed.)
  • Lab: 강의와 달리 프로그램을 직접 작성하는 시간. assembly · system programming 실습을 TA가 지도

CS 교과과정에서의 위치

  • CSED103 (프로그래밍 입문) → CSED211 → 3·4학년 시스템 과목들 (OS, Compilers, Networks, Computer Architecture, Embedded Systems, Databases, Performance Analysis …)
  • CSED211 = 이 과목들 전체의 Foundation of Computer Systems (HW · SW · networking의 기본 원리)

왜 지금 컴퓨터 시스템이 중요한가

  • 양쪽에서 변화가 동시에 일어나는 중
    • 위쪽: emerging applications — 현재는 AI(neural network)가 지배적, 새로운 사용 사례가 계속 등장
    • 아래쪽: hardware 혁신 — GPU, NPU 등 accelerator, GPU를 대체하려는 칩 회사들
  • 시스템 분야의 역할 = 두 변화 사이의 gap을 메우는 것 — 새로운 abstraction, principle, methodology를 정의해서 새 hardware를 효과적으로 쓰고 새 software를 올림
  • ⇒ 이 과목에서 배우는 것은 결국 abstraction을 배우는 것으로 귀결됨

2추상화 수준 (Level of Abstraction)

같은 프로세서, 보는 사람마다 다른 모습

  • Xeon Phi 사양 (semiconductor engineer 관점)
    • 80억 개 이상의 transistor, self-hosted manycore processor
    • 최대 72 cores, core당 4 SMT threads, 32개의 512-bit vector register
    • 최대 384GB DDR4-2400 main memory → 최대 115GB/s
    • 최대 16GB on-package MCDRAM (3D stacked) → 최대 400GB/s
  • programmer에게 이 사양은 직접적인 정보가 아님 → 모든 세부를 알 필요는 없음

  • 슬라이드 예시: 배열 100개 원소의 합을 구하는 loop. 왼쪽 hex = machine code, 오른쪽 = assembly code (사람이 읽는 텍스트 표현)

x9200 CONST R1, array
xD320 HICONST R1, array

xD520 HICONST R2, sum
x6640 LDR R3, R1, #0
x6880 LDR R4, R2, #0
x18C4 ADD R4, R3, R4
x7880 STR R4, R2, #0
x1261 ADD R1, R1, #1
x1BA1 ADD R5, R5, #1
x2B64 CMPI R5, #100
x03F8 BRn array_sum_loop
  • ADD R4, R3, R4 한 줄: "R3와 R4를 더해 R4에 저장" — 무엇을 하는지만 보여주고 data가 내부에서 어떻게 움직이는지는 숨김

손계산 2 · Machine Code(머신 코드) 한 줄 해독 (보충)

  • 슬라이드 ISA는 교육용 LC-4 형식으로 보임 (16-bit instruction, 앞 4 bit = opcode) (추정)
  • x18C4 = 0001 1000 1100 0100 → ADD R4, R3, R4  (0001=ADD · 100=Rd(R4) · 011=Rs(R3) · 000 · 100=Rt(R4))
  • x6640 = 0110 0110 0100 0000 → LDR R3, R1, #0  (0110=LDR · 011=Rd(R3) · 001=Rs(R1) · 000000=offset 0)
⇒ machine code = bit로 인코딩된 instruction, assembly = 그것의 텍스트 표현

Abstraction(추상화)의 정의와 프로그램 코드의 계층

정의 · Abstraction

하위 수준의 구현 세부를 숨기고 interface만 제공하는 것 → complexity를 다룰 수 있게 해준다. user는 "how"가 아니라 "what"에 관심을 갖는다 (hardware가 어떻게 만들어졌는지, data가 datapath에서 어떻게 움직이는지는 숨겨짐).
  • high-level 프로그램도 결국 하위 수준으로 번역되어 hardware 위에서 실행됨 → 그래서 abstraction이 중요
  • 이 과목의 관심 = 주로 assembly와 그 아래 수준

3앞으로 배울 주제

  • 교수 코멘트: bottom-up 방식 — 맨 아래 층부터 한 층씩 쌓아 올라감

Topic 목록 (bottom-up 순서)

  1. Bits, Bytes, Integers / Floating point: 데이터 하나가 hardware에 어떻게 저장되는가, 어떤 abstraction · guarantee가 제공되는가
  2. Machine-level programming (Control, Procedures, Data): assembly 수준에서 실제로 hardware가 하는 일
  3. Optimizations: 같은 결과를 내는 여러 방법 중 더 효율적인 방법
  4. Memory hierarchy, Cache memory: 프로그램 성능에 매우 중요
  5. Linking
  6. Exceptional control flow (Exceptions and processes, Signals): 예: 실행 중 divide-by-zero 에러가 아래에서 어떻게 처리되는가
  7. Virtual memory, Dynamic memory allocation: OS · 컴퓨터 구조 과목에서 반복해서 다시 나올 만큼 중요
  • 읽기: Ch.1 (오늘) → Ch.2.1 (다음 강의) → Ch.2.2~2.3 (그다음 강의)

1-3Xeon Phi 사양 계산★

최대 72 cores, core당 4 SMT threads인 Xeon Phi에서 동시에 실행 가능한 hardware thread 수와, 512-bit vector register 하나에 담기는 32-bit 정수의 개수를 구하라.

힌트
thread 수 = core × core당 thread. 레지스터 개수 = 레지스터 비트 수 ÷ 정수 하나의 비트 수.
정답

개념 정리는 힌트에 있음.

  1. hardware thread 수 = . — core당 4개씩
  2. register의 정수 개수 = . — 32-bit int 하나당 32 bit
정답 threads, 개
1-4Machine code 해독 (보충)★★

LC-4 형식에서 ADD(register)는 0001 ddd sss 000 ttt이다. x1AC2를 assembly로 해독하라.

힌트
hex 한 자리 = 4 bit. 16 bit로 펼친 뒤 opcode → Rd → Rs → Rt 순서로 자른다.
정답

개념 정리는 힌트에 있음.

  1. x1AC2를 이진수로 펼친다: 0001 1010 1100 0010. — hex → bit
  2. 필드대로 자른다: 0001 · 101 · 011 · 000 · 010. — opcode · ddd · sss · 000 · ttt
  3. 각 필드를 레지스터로 번역한다: 101 = R5, 011 = R3, 010 = R2.
정답ADD R5, R3, R2
