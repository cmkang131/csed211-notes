03. 5-3 [자작] ★★ Recursion(재귀)와 callee-saved

Lec4·6 · 프로시저/스택 | LAB : Bomb Lab

long fact(long n){ 
	if (n <= 1) return 1; 
	return n * fact(n-1); 
	}

fact: cmpq $1, %rdi
      jg   .L2
      movl $1, %eax
      ret
.L2:  pushq %rbx
      movq  %rdi, %rbx
      leaq  -1(%rdi), %rdi
      call  fact
      imulq %rbx, %rax
      popq  %rbx
      ret

(a) %rbx 를 push 하는 이유
(b) main 이 fact(4) 를 호출했을 때 가장 깊은 곳에서 스택에 쌓이는 바이트 수 (반환 주소 포함)
(c) 각 frame 이 저장한 %rbx 의 값

입출력·이해 예시

(별도 예시) main → fact(2) → fact(1)이면 반환 주소가 두 번 저장되고 pushq %rbx는 fact(2)에서 한 번 실행됨. 이때 사용량은 8×2+8=24B.


(a) 
%rbx가 calle-saved 변수니까 -> L2에 의해서, 내부에서 값이 바뀌어 버리면 안됨.

(b)
8 * (4 + 3) = 56 바이트.

!! 반환 주소 -> CALL 을 실행할 때마다, 반환 주소 8바이트가 스택에 쌓임.

(c)
%rbx 값 -> 4, 3 ,2 XX 틀림 // ?, 4, 3 을 저장함.
정답

(a) n 을 재귀 호출 뒤에 곱셈에 써야 하는데, %rdi 는 caller-saved 라 호출 중 바뀜. %rbx 는 callee-saved 라서 쓰려면 원래 값을 저장했다가 복원해야 함.

(b) fact(4), fact(3), fact(2) 는 각각 반환 주소 8 + 저장 rbx 8 = 16바이트, fact(1) 은 반환 주소 8만 (push 안 함) → 16*3 + 8 = 56바이트.

(c) fact(4) frame : main 의 %rbx, fact(3) frame: 4, fact(2) frame: 3. 반환값 4*3*2*1 = 24.
