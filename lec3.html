IEEE Floating-Point Standard(부동소수점 표준)

배경

  • IEEE 754 : 1985년 제정된 부동소수점 연산의 통일 표준 (IEEE 754-1985)
    • 이전에는 제조사마다 제각각인 형식
    • 모든 주요 CPU가 지원, 2008년 IEEE 854와 통합(754-2008), 2019년 소폭 개정
  • 수치 해석(numerical) 관점이 주도 → rounding, overflow, underflow, , 처리를 명확히 정의
    • 하드웨어 설계자는 단순함(→ two's complement처럼)을 원했지만 수치 해석가가 우세 → 하드웨어로 빠르게 만들기 어려움
    • 교수님 의견 : 좋은 수학적 성질이 우선이라는 수치 해석가 쪽을 지지

  • exponent : 의 거듭제곱으로 값에 가중치 → 0 쪽으로 줄이거나 큰 수 쪽으로 늘림
  • 인코딩 : MSB가 , 다음이 exp 필드 , 마지막이 frac 필드
    • 는 를 그대로 저장하지 않음 (bias로 변환), 도 을 그대로 저장하지 않음 (implied leading 1)

  • $1.40, $1.60, $1.50, $2.50, −$1.50 을 각 모드로 반올림

Round-to-Even(짝수 반올림)

  • 기본 모드인 이유 : 나머지 모드는 통계적으로 편향(biased)
    • 양수들의 합이 항상 과대 또는 과소 추정됨
  • nearest : 버리는 부분이 절반보다 작으면 내림, 크면 올림 → 버리는 부분이 균등 분포라면 50 : 50으로 공평
  • 문제는 정확히 절반(halfway)일 때 → 결과의 최하위 자리가 짝수가 되도록 → 절반은 올림, 절반은 내림 → 편향 없음
  • 소수 둘째 자리로 반올림
    • 1.2349999 → 1.23 : 절반 미만
    • 1.2350001 → 1.24 : 절반 초과
    • 1.2350000 → 1.24 : 정확히 절반, 3은 홀수 → 올림
    • 1.2450000 → 1.24 : 정확히 절반, 4는 짝수 → 내림

Binary Rounding(이진수 반올림)

  • even : 최하위 비트(LSB)가 0
  • halfway : rounding 위치 오른쪽 비트들이
    • 버리는 첫 비트가 0 → 절반 미만 → 버림
    • 버리는 첫 비트가 1이고 뒤에 1이 하나라도 → 절반 초과 → 올림
    • 버리는 첫 비트가 1이고 뒤가 전부 0 → 정확히 절반 → even 쪽으로

  • Closed under addition : Yes, 단 나 NaN이 나올 수 있음
  • Commutative : Yes
  • Associative : No, overflow, rounding의 부정확성
  • Identity : 0
  • Inverse : Yes, ·NaN 제외 ()
  • Monotonicity : Yes, ·NaN 제외
  • 결합법칙 반례 (float 기준)
  • 에 맞춰 3.14를 오른쪽 shift → significand 범위를 벗어나 사라짐 → 결과 0
  • numpy float32로 확인 : 0.0 / 3.14
  • double에서는 → 0은 아니지만 역시 오차 (보충, python 확인)
  • 수업 중 일화 : vector clock(분산 협업 편집에서 편집 순서를 정하는 논리 시계)을 floating point로 압축하려던 연구에서 rounding error가 문제 → 연산이 누적되면 실제로 심각한 문제

곱셈의 수학적 성질 (Commutative Ring(가환 환)과 비교)

Floating Point 만들기 (Creating FP Number)

세 단계

  • ① Normalize : leading 1이 오도록 binary point 이동 ( 꼴), 왼쪽으로 옮긴 만큼 exponent 증가
  • ② Round : frac 비트 수에 맞게 반올림
  • ③ Post-normalize : rounding으로 가 되면 오른쪽 shift 1, exponent 1 증가

Guard(가드) · Round(라운드) · Sticky(스티키)

  • Guard bit G : 결과에 남는 마지막 비트(LSB)
  • Round bit R : 버려지는 첫 비트
  • Sticky bit S : R 뒤 나머지 비트 전체의 OR → 1이 하나라도 있는지 하드웨어가 OR로 확인
  • R = 0 : 나머지 0.5 미만 → 버림
  • R = 1, S = 1 : 나머지 0.5 초과 → G 자리에 1 더함 (올림)
  • R = 1, S = 0 : 나머지 = 0.5 → round to even : G = 1이면 올림, G = 0이면 버림

C에서의 Floating Point(부동소수점)

Float(부동소수점)와 Double(배정밀도), Casting(형 변환)

  • C의 두 precision : float (single), double (double)
  • int · float · double 사이의 casting은 비트 표현을 바꿈 (값을 보존하려고 재인코딩)
  • double/float → int : 소수부 truncate (round toward zero), 범위 밖·NaN은 정의되지 않음 → 보통 TMin
  • int → double : 정확히 변환 (int가 53비트 이하이면) → 32비트 int는 frac 52비트 + leading 1에 다 들어감
  • int → float : frac이 23비트뿐 → rounding mode에 따라 반올림될 수 있음
  • int → FP 변환 = 최상위 1이 leading 1이 되도록 오른쪽 shift, 그 뒤 비트가 frac
    • 32비트 int는 최대 31번 shift → 뒤 31비트가 double의 52비트 frac에는 들어가지만 float의 23비트에는 안 들어감
  • TMin을 특수값으로 쓰는 이유 : two's complement에서 로 비대칭 → 예외 표시용으로 사용

손계산 5 : int → Float(부동소수점) 손실

    • → frac 23비트 뒤에 1이 하나 남음 → R = 1, S = 0, G = 0 → halfway, 짝수 쪽으로 버림
    • (int)(float)x = 16777216 ≠ x
  • python numpy로 확인 : int(np.float32(16777217)) → 16777216
    • (int)(double)x는 그대로 16777217

Floating Point Puzzle(부동소수점 퍼즐)

  • int x; float f; double d; (d, f는 NaN 아님)
  • x == (int)(float) x → 거짓 : float frac 23비트 → 큰 int는 rounding (예: 16777217)
  • x == (int)(double) x → 참 : 32비트 int는 double에 정확히 들어감
  • f == (float)(double) f → 참 : 작은 표현 → 큰 표현 → 다시 작은 표현, 정보 손실 없음
  • d == (float) d → 거짓 : double → float에서 정밀도·범위 손실
  • f == -(-f) → 참 : 부호 반전은 sign bit만 뒤집음
  • 2/3 == 2/3.0 → 거짓 : 2/3은 정수 나눗셈 = 0, 2/3.0은 0.666…
  • d < 0.0 ⇒ ((d*2) < 0.0) → 참 : 음수×2는 더 작은 음수, overflow해도
  • d > f ⇒ -f > -d → 참 : 부호만 뒤집으므로 대소 반전이 정확함
  • d * d >= 0.0 → 참 : 같은 부호 곱, overflow해도
  • (d + f) - d == f → 거짓 : 결합법칙 불성립 (예: d가 매우 크면 f가 rounding으로 사라짐)
  • 녹취에서 일부 항목 판정이 STT로 불분명 → 위 답은 CS:APP 표준 풀이 기준 (보충)

요약

  • IEEE FP는 명확한 수학적 성질을 가짐
  • 꼴의 수를 표현
  • 연산은 구현과 무관하게 추론 가능 → 완벽한 정밀도로 계산한 뒤 round한 것처럼
  • 실수 연산과 같지 않음 → 결합법칙·분배법칙 위반 → 컴파일러, 수치 소프트웨어 작성이 어려워짐

시험 포인트

  • fractional binary : 꼴만 정확히 표현, 1/3 · 1/5 · 1/10은 반복 비트
  • 필드 비트 수 : single 1/8/23 (bias 127), double 1/11/52 (bias 1023)
  • normalized : , / denorm : , / exp all-1 : 또는 NaN
  • denorm이 를 쓰는 이유 : 최소 normalized와 같은 간격 → gradual underflow, smooth transition
  • 과 구분, NaN 예 (, , )
  • 15213.0 → 0x466DB400 같은 인코딩 / 디코딩 손계산
  • tiny 8-bit (bias 7) 표 : 최소 denorm 1/512, 최대 denorm 7/512, 최소 norm 8/512, 최대 norm 240
  • 값 분포 : 0 근처 촘촘, exp 1 증가마다 간격 2배
  • 비트 패턴이 단조 → unsigned 비교로 대소 비교 가능 (부호, ±0, NaN 예외)
  • rounding 4모드 표, round-to-even이 기본인 이유 (통계적 편향 없음)
  • 이진 반올림 : G · R · S 규칙, halfway면 LSB 짝수로
  • FP 곱셈 : , , / 덧셈 : 지수 맞춰 shift 후 더하고 정규화
  • 결합법칙·분배법칙 불성립 반례 (3.14 + 1e10 − 1e10, 1e20 × 1e20 − …)
  • 변환 3단계 normalize → round → post-normalize (63 → 64 사례)
  • C casting : FP → int는 truncate, int → double 정확, int → float 반올림 가능, puzzle 10개
