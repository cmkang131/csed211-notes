C의 Bitwise Operator vs Logical Operator

  • & | ~ ^ (bitwise): 모든 integral 타입(long, int, short, char, unsigned …)에 적용, 인자를 비트 벡터로 보고 bitwise 적용
    • ~0x41 = ~01000001 → 10111110 = 0xBE · ~0x00 → 0xFF
    • 여기서는 CS:APP식 8비트 벡터 예시 — C의 int 식에서는 int 전체 비트가 반전됨 (하위 8비트만 보려면 & 0xFF로 마스킹)
    • hex ↔ binary 변환 요령: 4비트씩 잘라 각각 변환 (0x41 → 0100 | 0001)
  • && || ! (logical): 값 전체를 True/False 하나로 축약: 0만 False, 0이 아니면(양수든 음수든) True, 결과는 항상 0 또는 1
    • !0x41 → 0x00 · !0x00 → 0x01 · !!0x41 → 0x01 (원래 값이 아니라 1!)
    • 0x69 && 0x55 → 0x01 · 0x69 || 0x55 → 0x01
&& vs &, || vs | 혼동: 0x69 & 0x55 = 0x41 이지만 0x69 && 0x55 = 0x01. !!x는 원래 값이 아니라 0 또는 1이다.

Shift 연산

left shift x << y
왼쪽으로 y칸 이동, 넘친 비트는 버림, 오른쪽은 0으로 채움
right shift x >> y
오른쪽으로 y칸 이동, 넘친 비트는 버림
logical shift
왼쪽을 0으로 채움 (값의 의미는 고려 안 함)
arithmetic shift
왼쪽을 MSB 복제로 채움
  • 수치적 의미: 왼쪽 1칸 = ×2, 왼쪽 k칸 = / 오른쪽 1칸 = ÷2
    • signed 정수에서 MSB는 음수 weight → 음수를 2로 나눠도 음수여야 하므로 MSB가 1이면 1로 채워야 함 (arithmetic shift의 이유)
    • C 표준 기준: unsigned right shift는 logical(0 채움) · 음수의 signed right shift는 구현 정의 (일반적인 x86은 arithmetic) · signed left shift는 overflow 시 UB

Undefined behavior

shift 양이 0보다 작거나 word size 이상이면 undefined → 기계마다 다름 (exception을 내기도, 음수를 아주 큰 양수로 해석하기도). shift는 보수적으로 사용.

3Integer Representation: Unsigned와 Two's Complement

Encoding 공식

unsigned: 모든 위치가 양의 weight, 켜진 비트의 weight를 합산
two's complement: 하위 비트 weight는 unsigned와 동일, MSB만 음의 weight
  • sign bit = MSB: 0이면 nonnegative, 1이면 negative
    • MSB 하나만으로 음수가 보장되는 이유:
    • 하위 비트를 전부 켜도() MSB의 절댓값보다 1 작음 → MSB가 켜지면 무조건 음수

왜 Sign-Magnitude가 아니라 Two's Complement인가

  • 직관적 대안: MSB = 부호, 나머지 = 크기 (예 4비트: 0011 = +3, 1011 = −3)
  • 문제 ① 0000 = +0, 1000 = −0 → 0이 두 개, 패턴 낭비
  • 문제 ② 덧셈 하드웨어가 복잡: 부호가 같으면 더하고, 다르면 크기 비교 → 큰 쪽에서 작은 쪽을 빼고 큰 쪽 부호 → adder와 별도 subtractor 필요
  • two's complement: 양수 · 음수 조합 상관없이 같은 adder로 그냥 더하면 정답 → 하드웨어 면적 · 에너지 절약
    • 뺄셈도 , → subtractor 불필요

5Extension과 Truncation

Sign Extension

  • 목표: 비트 signed 를 같은 값을 갖는 비트 로
  • 규칙: 부호 비트 를 개 복사해 앞에 붙임
  • zero extension: 앞을 0으로 채우면 값 유지 (전부 양의 weight)
  • signed에서 음수를 0으로 채우면 → 양수로 바뀌어 의미 붕괴 → MSB 복사 필요

Unsigned Addition

  • 비트 두 수의 참 합은 최대 비트 → carry를 버림 → 결과 비트
  • MSB 밖으로 carry가 나가면 = unsigned overflow (결과가 참 합보다 작음)

Two's Complement Addition

  • TAdd와 UAdd는 비트 수준에서 동일 → 같은 adder 사용
  • 적용 범위: TMax+1 = TMin 같은 wrap 규칙은 비트 벡터/기계 모델의 항등식 — C의 unsigned 연산은 모듈로로 보장되지만 signed overflow는 C 표준상 UB
int s, t, u, v;
s = (int) ((unsigned) u + (unsigned) v);
t = u + v;
// 항상 s == t

  • 참 합 비트 → MSB(carry) 버림 → 남은 비트를 two's complement로 해석

    • 양수 + 음수: 불가능, 결과가 항상 두 피연산자 사이 → 범위 안

  • 비트 × 비트의 정확한 결과는 비트를 넘을 수 있음
    • Unsigned 최대: 비트,
    • Two's comp. 최소: 비트,
    • Two's comp. 최대: 비트 (일 때만),

  • C의 표준 곱셈: 상위 비트를 버림 → 덧셈(1비트 버림)보다 버리는 양이 많아 overflow가 훨씬 흔함

Unsigned를 언제 쓰나

쓰지 말 것: 함의를 모른 채 unsigned 사용

실수하기 쉽고 매우 미묘하다:

unsigned i;
for (i = cnt-2; i >= 0; i--)   // i >= 0 은 항상 참 → 무한 루프
    a[i] += a[i+1];
  • unsigned i가 0에서 1 감소 → UMax로 wrap around, 절대 0보다 작아지지 않음
#define DELTA sizeof(int)
int i;
for (i = cnt; i - DELTA >= 0; i -= DELTA)   // 역시 항상 참
    ...
  • i는 signed지만 sizeof가 unsigned(size_t)를 반환 → i - DELTA가 unsigned로 계산 → 0 미만 불가
  • 쓸 것: modular arithmetic (multi-precision 연산), 집합 표현 (logical right shift, sign extension 없음)

Unsigned로 거꾸로 세기 (Robert Seacord, "Secure Coding in C and C++")

C 표준은 unsigned 덧셈이 modular arithmetic임을 보장: .

for (i = cnt-2; i < cnt; i--)   // 0 다음 UMax가 되면 i < cnt 가 거짓 → 종료
    a[i] += a[i+1];

더 좋은 방법: size_t (word size 길이의 unsigned, 64-bit에서 8바이트). cnt가 4바이트 unsigned의 UMax여도 index가 더 넓어서 동작:

7Memory에서의 표현

Byte-Oriented Memory와 Machine Word

  • 프로그램은 virtual address 사용: 메모리를 아주 큰 byte 배열로 간주 (실제와 다르지만 그렇게 생각해도 됨)
    • address = 배열 index, pointer 변수 = address를 저장
    • 시스템은 프로세스마다 private address space 제공. process = 실행 중인 프로그램. 다른 프로세스 데이터는 접근 불가 (OS의 보호, virtual memory, 이후 강의)
  • word size: 정수 데이터의 명목상 크기, 더 정확히는 address 크기 (일반적으로 가상 주소·포인터 폭과 일치 — 엄밀히는 CPU가 자연스럽게 처리하는 데이터 폭)
    • CPU 레지스터 폭과 일치 (32-bit 기계 = 32비트 레지스터), program counter 같은 레지스터가 메모리 주소를 가리킴
  • 32-bit (4 bytes): 주소 공간 bytes = 4 GiB · 64-bit: 이론상 bytes = 16 EiB bytes
    • 슬라이드에는 "18 PB, 18.4 × 10¹⁵"로 적혀 있으나 이므로 18 EB가 맞음 (교수도 녹취에서 exabyte로 설명)
    • 실제로는 64비트 전부를 주소로 쓰지 않음 → 실용 한계 약 256 TB ( bytes에 해당)
  • address는 byte 위치를 지정, word의 address = word의 첫 바이트 address. 연속된 word의 address 차이: 4 (32-bit), 8 (64-bit)
    • 4바이트 word 주소는 하위 2비트가 항상 00, 8바이트 word 주소는 하위 3비트가 항상 000. 이 하위 비트들은 word 안에서 몇 번째 byte인지 offset으로 사용

Byte Ordering · Endianness

Big Endian: most significant byte가 가장 낮은 address (Sun, PowerPC Mac, IBM, Internet)
Little Endian: least significant byte가 가장 낮은 address (x86, Android · iOS · Windows를 돌리는 ARM)
암기법: Little endian = Least significant byte at Lowest address
  • 정수의 실제 바이트 배치 (낮은 주소 → 높은 주소)
    • int a = 15213 (0x00003B6D): IA32/x86-64 (little) 6D 3B 00 00 · Sun (big) 00 00 3B 6D
    • int b = −15213 (0xFFFFC493): IA32/x86-64 93 C4 FF FF · Sun FF FF C4 93
    • long c = 15213: IA32 6D 3B 00 00 (4B) · x86-64 6D 3B 00 00 00 00 00 00 (8B) · Sun 00 00 3B 6D

  • ② ux >= 0
  • ③ x > 0 && y > 0 ⇒ x + y > 0
  • ④ x >= 0 ⇒ -x <= 0
  • ⑤ x <= 0 ⇒ -x >= 0
  • ⑥ ux >> 3 == ux/8
  • ⑦ x >> 3 == x/8
