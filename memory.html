2캐시 주소 해석 (Address → Tag / Set / Offset)

  • 물리 주소는 tag (t_cache bits) · set index (s bits) · block offset (b bits)으로 쪼개진다. S = 2s개 set, block 크기 B = 2b
  • 주소가 어느 set으로 가는지는 set index bits만이 결정. 같은 set 안에서는 tag 비교로 hit/miss가 갈림
  • 주소 길이가 m bits이고 set index가 s bits, block offset이 b bits이면 tag는 t_cache = m − s − b bits이다. 따라서 주소는 tag, set index, block offset 순으로 분해된다.
  • Set 수는 S = 2s, block 크기는 B = 2b bytes, set당 line 수는 E이다. 캐시의 데이터 용량은 C = S × E × B bytes이며, 이 계산에서는 tag·valid bit 등의 메타데이터를 제외한다.
  • 바이트 주소 A에서 block offset은 A mod 2b, set index는 ⌊A / 2b⌋ mod 2s, tag는 ⌊A / 2s+b⌋로 계산한다.
  • 직접 사상(direct-mapped, E=1)은 충돌이 잦고, E-way set associative는 그 충돌을 E개 라인으로 흡수

3캐시 시뮬레이터 (Hit / Miss / Eviction)

  • 접근 순서(주소 trace)가 hit rate을 결정한다. Cache Lab (Part A/B) 전에 손으로 trace를 따라가 보는 연습용
  • miss를 구분해 볼 것 — Cache miss의 종류
    • Cold (compulsory) miss: 해당 메모리 block에 처음 접근할 때 발생한다.
    • Conflict miss: 여러 block이 같은 set에 매핑되어 set의 E개 line을 초과하면서 발생한다. 같은 용량과 block 크기를 가진 fully associative cache에서는 hit였을 miss이다.
    • Capacity miss: 필요한 working set을 캐시 전체에 담을 수 없어 발생하며, 같은 용량의 fully associative cache에서도 발생할 miss이다.
    • Eviction: 해당 set의 모든 line이 유효한 상태에서 새로운 block을 적재하기 위해 기존 line을 교체하는 것이다.
    • Valid bit의 한계: Valid bit는 현재 line의 유효성만 알려 준다. 과거에 접근했지만 이미 캐시에서 쫓겨난 block인지까지는 알려 주지 않는다. 따라서 miss 종류는 전체 접근 trace를 분석하여 판별해야 한다.
  • LRU: set이 꽉 차면 가장 오래 전에 쓰인 라인이 쫓겨남

첫 번째 접근은 해당 block이 미리 적재되어 있지 않으므로 miss가 발생합니다.

LRU: 각 set에서 마지막 접근 시각이 가장 오래된 valid line을 교체합니다. hit 시에도 마지막 접근 시각을 갱신합니다. 캐시는 처음에 모두 invalid 상태이며, write/modify 명령은 다루지 않습니다.

4가상 메모리 (VA → PA Translation)

  • 가상 주소는 VPN (virtual page number) + VPO (page offset). 페이지 크기 P = 2p면 VPO는 하위 p bits
  • CPU는 먼저 TLB에서 VPN을 찾고, miss면 page table에서 PTE를 읽는다. PTE의 valid bit가 0이면 page fault (교육용 resident-bit 단순화: 실제로는 invalid PTE가 미매핑을 뜻할 수도 있고 fault가 항상 disk I/O는 아님). 시뮬레이터의 TLB는 cache-sim과 달리 단순 교체 모델(고정 way)이라 LRU가 아님에 주의
  • 물리 주소는 PPN + VPO를 그대로 이어붙인 것 (PPO = VPO)
