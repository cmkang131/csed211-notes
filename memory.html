Memory Hierarchy · Cache · Virtual Memory

이후 진도 미리보기 (Lec1 교수 슬라이드의 topic 순서: memory hierarchy/cache → linking → ECF → VM → malloc) · 중간고사(Lec2~8) 범위 밖 · 교수 원본 슬라이드 공개 전이라 CS:APP 3판 / CMU 15-213 기준으로 구성, 강의 진도 나가면 원본 기준으로 보강

1메모리 계층 (Memory Hierarchy)

  • 핵심 직관: 위로 갈수록 빠르고 · 작고 · (byte당) 비쌈. Lec4 슬라이드 그림의 계층(Register → Cache → Main memory → SSD/Disk)을 CS:APP 기준으로 확장한 것
  • register는 사실상 1 cycle 접근. cache miss로 main memory까지 내려가면 수백 cycle (Lec4 슬라이드 기준)
  • 아래 위젯에서 각 층을 클릭해 대표 크기·지연과 "L1 = 1초" 환산 스케일을 확인할 것

2캐시 주소 해석 (Address → Tag / Set / Offset)

  • 물리 주소는 tag (t bits) · set index (s bits) · block offset (b bits)으로 쪼개진다. S = 2s개 set, block 크기 B = 2b
  • 주소가 어느 set으로 가는지는 set index bits만이 결정. 같은 set 안에서는 tag 비교로 hit/miss가 갈림
  • 직접 사상(direct-mapped, E=1)은 충돌이 잦고, E-way set associative는 그 충돌을 E개 라인으로 흡수

3캐시 시뮬레이터 (Hit / Miss / Eviction)

  • 접근 순서(주소 trace)가 hit rate을 결정한다. Cache Lab (Part A/B) 전에 손으로 trace를 따라가 보는 연습용
  • cold miss (처음 접근, valid=0) / conflict miss (같은 set에 다른 tag가 이미 차 있음)를 구분해 볼 것
  • LRU: set이 꽉 차면 가장 오래 전에 쓰인 라인이 쫓겨남

4가상 메모리 (VA → PA Translation)

  • 가상 주소는 VPN (virtual page number) + VPO (page offset). 페이지 크기 P = 2p면 VPO는 하위 p bits
  • CPU는 먼저 TLB에서 VPN을 찾고, miss면 page table에서 PTE를 읽는다. PTE의 valid bit가 0이면 page fault → disk에서 페이지를 가져옴
  • 물리 주소는 PPN + VPO를 그대로 이어붙인 것 (PPO = VPO)
