Lecture 5 · Machine-Level Programming II: Control

10/8 (목) · 10/13 (녹화) · 슬라이드 "Lecture 5 Control" (전체) + 10/8 수업 녹취 + 10/13 녹화 강의 (조건 코드 ~ switch)

1제어 흐름과 프로세서 상태

왜 control이 필요한가

  • 기본 동작: 명령어를 읽고 실행한 뒤 %rip를 그 명령어 크기만큼 증가 → 다음 명령어로 순차 진행 (소스 코드를 한 줄씩 진행하는 것과 같음)
  • 반복문 끝에서 조건이 만족되면 루프 처음으로 되돌아가야 함 → jump
  • 조건에 따라 다른 분기로 가야 함 → 이를 처리하는 것이 control flow
  • 이번 강의 주제: 조건 코드 → 조건 분기 → 반복문 → switch문: C의 if / loop / switch가 기계어 수준에서 어떻게 구현되는지

Processor State (x86-64, 일부)

  • %rax, %rbx, … %r15: 범용 레지스터, 임시 데이터 저장 · %rsp: runtime stack의 top 위치
  • %rip: instruction pointer: 다음에 실행할 명령어 주소 (general purpose 16개와 별개)
  • CF ZF SF OF: condition codes, 최근 연산 결과의 상태

핵심: condition code + %rip = 조건 분기

연산 결과로 flag가 세팅됨 → 특정 조건이 만족되면 %rip를 특정 위치로 갱신(jump). 어디로 갈지는 직전 연산이 세팅한 조건 코드(CF, ZF, SF, OF)가 결정 → %rip와 조건 코드는 밀접하게 연결됨. 루프 안의 점프, switch 상태 이동이 모두 이 조합으로 구현된다.

2Condition Codes

네 가지 flag (모두 1-bit 레지스터)

flag이름set 조건주 해석
CFCarry FlagMSB에서 carry out (뺄셈이면 borrow)unsigned overflow
ZFZero Flag결과가 0공통
SFSign Flag결과의 MSB가 1 (signed로 음수)signed
OFOverflow Flagtwo's complement overflowsigned

Implicit setting(산술 명령의 부수효과)

  • 산술 명령을 실행할 때마다 flag가 결과 상태를 반영하도록 자동 갱신 (side effect). 예: addq src, dst ↔
    • CF: MSB에서 carry out → unsigned overflow (결과가 해당 크기에 담기지 않는 경우)
    • ZF: 이면 set · SF: (signed, MSB=1)이면 set
    • OF: two's complement overflow: a, b가 양수인데 t가 음수, 또는 a, b가 음수인데 t가 0 또는 양수
덧셈의 OF: . 부호가 다른 두 값(양수+음수)을 더하면 overflow는 절대 발생하지 않음
  • leaq는 flag를 바꾸지 않음 (주소 계산 전용)

해석은 사용자의 몫

하드웨어는 덧셈이 signed인지 unsigned인지 모름 → CF와 OF를 둘 다 계산해서 세팅. unsigned 덧셈으로 볼지 signed 덧셈으로 볼지는 프로그래머·컴파일러의 해석. unsigned로 보면 CF를, signed로 보면 OF를 본다. 같은 flag 비트가 상황에 따라 두 가지 의미로 쓰인다는 것을 기억할 것.

cmp와 test: flag를 명시적으로 세팅

cmp (compare)

  • cmpq src2, src1: cmpq b, a는 를 계산하되 destination에 저장하지 않음. 레지스터는 갱신하지 않고 flag 세팅만 목적
  • 피연산자 순서 주의: 두 번째 operand − 첫 번째 operand. cmpq %rsi, %rdi → %rdi − %rsi
  • CF: (unsigned)면 borrow 발생 → set · ZF: , 즉 면 set · SF: (signed)이면 set · OF: two's complement overflow 시 set
뺄셈의 OF:
  • 뺄셈에서의 CF: a − b는 내부적으로 로 계산 → 실제로 MSB에서 carry out이 나면 CF = 0, 안 나면 CF = 1. carry out이 안 났다 = 위에서 빌려왔다(borrow) = unsigned로 . 즉 CF는 "실제 carry 비트"가 아니라 "borrow가 있었는가".
8bit 예시a + (~b+1)carry outCF의미
3 − 200000011 + 11111110있음03 ≥ 2 (unsigned)
1 − 200000001 + 11111110없음11 < 2 (unsigned), 결과 11111111 = −1

test

  • testq src2, src1: testq b, a는 를 계산(AND)하되 저장하지 않음
  • operand 하나를 mask로 두면 유용. 특정 비트만 1인 마스크를 주면 a의 그 비트가 1인지 ZF로 판단
  • ZF: 이면 set · SF: 이면 set (MSB=1) · CF, OF는 항상 clear(0). AND 연산에는 carry/overflow 개념이 없음
  • 대표 용법: testq %rax, %rax: 자기 자신과 AND → 결과 = 원래 값 그대로 → ZF=1이면 %rax가 0, SF=1이면 음수 (0인지 음수인지 한 번에 확인)
  • 정리: flag는 산술 연산으로도, cmp/test로도 세팅됨. 대부분 두 값을 비교하는 용도. cmp로 의 부호·overflow·0 여부 확인, test로 0/음수 확인.

3setX(flag 읽기)

setX 명령

  • setX dst: condition code 조합에 따라 dst의 최하위 1 byte만 0 또는 1로 세팅. 나머지 7 byte는 바꾸지 않음 → 위쪽 byte에 남아 있던 값이 그대로 남을 수 있음
명령조건식의미
sete / setneZF / ~ZFEqual·Zero / Not Equal·Not Zero
sets / setnsSF / ~SFNegative / Nonnegative
setg / setge~(SF^OF) & ~ZF / ~(SF^OF)Greater / Greater or Equal (signed)
setl / setleSF^OF / (SF^OF) | ZFLess / Less or Equal (signed)
seta / setb~CF & ~ZF / CFAbove / Below (unsigned)
  • 쉬운 것: sete(cmp로 계산 → 같으면 0 → ZF=1 → dst = 1), sets(결과가 음수 → SF=1 → dst = 1).

핵심: setl = SF ^ OF

signed less 판정에 SF와 OF를 함께 봄. SF만 보면 안 되는 이유: overflow가 나면 결과의 부호가 뒤집힘.
  • 경우 ① overflow 없음 (OF=0) → 결과 부호가 그대로 맞음 → SF=1이면
  • 경우 ② overflow 발생 (OF=1) → 부호가 뒤집힘 → SF=0인데도 실제로는 (예: 왼쪽이 아주 작은 음수, 오른쪽이 아주 큰 양수)
  • 두 경우를 합치면 . unsigned 비교는 CF로: (below) ⇔ CF=1.

손계산 2 · cmp 4, 2 → setl (수업 예시)

cmpb $4, %al, %al = 2 → , 이므로 setl 결과가 1이어야 함.

2 = 00000010, 4 = 00000100. 뺄셈 = 덧셈 + two's complement:
−4: 4를 반전(11111011) → +1 → 11111100
00000010 + 11111100 = 11111110 (= −2)
flag: ZF = 0 (결과 ≠ 0) · SF = 1 (MSB=1) · OF = 0 (양수−양수는 overflow 불가) · CF = 1 (unsigned 2 < 4 → borrow)
결과setl = SF ^ OF = 1 ^ 0 = 1 → less 조건 만족 · setb = CF = 1 → unsigned로도 2 < 4

손계산 3 · overflow가 끼는 비교 (8-bit, cmp b, a 기준 a − b)

a, b8-bit 결과SFOFZFCFsetl판정
a = −2, b = −111111111 (−1)10011−2 < −1 ✓
a = −100, b = 10000111000 (+56)01001−100 < 100 ✓
a = 100, b = −10011001000 (−56)11010100 > −100 ✓

  • 두 번째 줄: 진짜 값 −200은 8-bit 범위(−128~127) 밖 → overflow로 +56 → SF=0이지만 OF=1이 보정 → setl = 1. SF만 봤다면 "−100 ≥ 100"이라는 틀린 결론.
  • 세 번째 줄: 진짜 값 +200 → overflow로 −56 → SF=1이지만 OF=1 → setl = 0.
8bit: cmp $1, a (a = -128 = 10000000)
a - 1 = 01111111 (+127)  SF=0 OF=1 CF=0

(교수님은 "-256"이라고 말했지만 8bit 최소값은 −128. 원문 교정)

  • loop과의 연결: less 조건이 중요한 이유는 반복문: 매 반복마다 i < count인지 비교 → 만족하면 계속, 아니면 탈출. 밑에서는 cmp로 flag를 세팅하고 그 flag 조합으로 조건 유지 여부를 판단.

Byte Register와 movzbl

  • setX는 byte 레지스터 하나에 씀. 모든 정수 레지스터는 최하위 byte를 이름으로 참조 가능: %al, %bl … (%rax 64bit, %eax 32bit, %ax 16bit, %ah/%al 상위/하위 8bit)
  • setX하면 앞의 56-bit는 그대로 남음 → %al=1은 되지만 %rax=1은 아님 → 보통 movzbl로 마무리
  • movzbl: byte → 32-bit zero extension (1바이트 값을 4바이트로 확장하며 나머지를 0으로 채움). 32-bit 명령은 64-bit 레지스터의 상위 32 bit도 0으로 만듦 → %rax 전체가 0 또는 1
  • 예: movzbl %al, %eax: %rax = 0x123456789ABCDE01 → %rax = 0x0000000000000001

손계산 4 · C → assembly, gt

int gt(long x, long y) { return x > y; }
gt:
    cmpq  %rsi, %rdi  # x − y 로 flag 세팅 (x:y 비교)
    setg  %al         # x > y 이면 %al = 1
    movzbl %al, %eax  # 나머지 비트 0 (%rax 전체)
    ret
  • %rdi = x, %rsi = y, %rax = 반환값
  • x = 5, y = 3: 5 − 3 = 2 → ZF=0, SF=0, OF=0 → setg = ~(0^0) & ~0 = 1 → 반환 1
  • x = 3, y = 3: ZF=1 → setg = 0 → 반환 0

4Conditional Branch

jX 명령

  • jX: 조건 코드에 따라 다른 위치로 점프 · jmp는 조건 없이 항상 점프 (unconditional)
  • je · jne · js · jns · jg · jge · jl · jle · ja · jb: setX와 같은 조건식을 점프에 적용한 것
  • signed 비교: jg, jge, jl, jle (SF^OF 사용) · unsigned 비교: ja, jb (CF 사용)

absdiff: 옛날 방식 분기

gcc -Og -S -fno-if-conversion control.c. −Og: 최적화를 거의 안 해 C 구조를 그대로 따름 · −fno-if-conversion: if/else를 cmov로 바꾸지 말고 분기로 남기라는 플래그

long absdiff(long x, long y) {
    long result;
    if (x > y) result = x - y;
    else       result = y - x;
    return result;
}
absdiff:
    cmpq %rsi, %rdi  # x:y
    jle  .L4         # x <= y 이면 else로
    movq %rdi, %rax
    subq %rsi, %rax  # result = x − y
    ret
.L4:                 # x <= y
    movq %rsi, %rax
    subq %rdi, %rax  # result = y − x
    ret
  • x는 %rdi, y는 %rsi, 반환값은 %rax. cmpq %rsi, %rdi → x − y로 플래그 세팅, jle .L4 → x ≤ y면 else 블록으로 점프
  • C 조건과 반대 조건(x > y → jle)으로 else로 점프
  • .L4 같은 label: 코드 안 위치를 사람이 읽기 쉬운 이름으로 붙인 것, 어셈블러가 실제 주소로 바꿔줌

goto 버전으로 보기

  • goto: label 위치로 바로 점프 → 어셈블리 분기를 C로 추상화한 형태. 실제 코딩에서는 spaghetti code를 만들어 거의 안 쓰지만, 컴파일러가 C를 어떻게 점프로 바꾸는지 공부할 때는 어셈블리와 1:1 대응이라 훨씬 읽기 쉬움
long absdiff_j(long x, long y) {
    long result;
    int ntest = x <= y;
    if (ntest) goto Else;
    result = x - y;
    return result;
Else:
    result = y - x;
    return result;
}

일반적인 조건식 변환: val = test ? then_expr : else_expr;

    ntest = !(test);
    if (ntest) goto Else;
    val = then_expr;
    goto Done;
Else:
    val = else_expr;
Done:
  • then과 else를 별도 코드 영역으로 만들고 조건에 맞는 쪽만 실행. absdiff는 각 블록에서 바로 return했지만 실제로는 if/else 뒤에 코드가 이어지므로 then 끝에서 goto Done으로 합류 지점에 점프 (else는 끝나면 그대로 Done으로 흘러감, 점프 불필요)

5Conditional Move

왜 분기를 피하는가: 파이프라인

  • 명령어 하나는 여러 단계로 나뉨 (명령 해석 → 데이터 읽기 → 연산 → 메모리 쓰기). 빨래 비유: 세탁 → 건조 → 개기. 1번 빨래가 건조기로 가면 세탁기가 비니까 2번 빨래를 바로 세탁 시작
  • 단계 수만큼 명령어를 겹쳐 동시 실행 = pipeline. 예전 4~5단계, 지금은 20단계 정도 → 단계가 많을수록 성능 향상 폭이 큼
  • 분기는 파이프라인을 깨뜨림. 조건을 계산하기 전까지 다음 명령이 어디 있는지 모름. 미리 가져와 실행하던 명령이 틀렸으면 다 버리고 점프 대상에서 새로 가져와야 함 → 컴파일러는 분기를 최대한 안 쓰려 함

cmov의 아이디어

  • conditional move (cmovX src, dst): if (test) dst = src를 명령어 하나로 수행 (1995년 이후 x86 지원)
  • then과 else를 둘 다 미리 계산해 "양손에 들고" 있다가, 플래그를 보고 하나를 고름 → 점프 없음
    result = then_expr;
    eval = else_expr;
    nt = !(test);
    if (nt) result = eval;
    return result;
absdiff:
    movq %rdi, %rax
    subq %rsi, %rax   # result = x − y
    movq %rsi, %rdx
    subq %rdi, %rdx   # eval = y − x
    cmpq %rsi, %rdi   # x:y
    cmovle %rdx, %rax # x <= y 이면 result = eval
    ret
  • rax = x − y, rdx = y − x를 다 계산한 뒤 cmpq로 비교 → cmovle: x ≤ y면 rax를 rdx로 덮어씀
  • 장점: 점프가 없어 파이프라인 손실 없음 · 단점: 둘 중 하나만 필요한데 둘 다 계산 → then/else 계산이 얼마나 가벼운지에 달림

cmov를 쓰면 안 되는 경우: GCC는 안전하다고 확신할 때만 사용

  • 비싼 계산: val = test(x) ? hard1(x) : hard2(x) → 둘 다 계산하므로 손해, 계산이 아주 간단할 때만 이득
  • 위험한 계산: val = p ? *p : 0 → p가 null이어도 *p를 계산해버림 → null pointer 역참조
  • 부작용 있는 계산: val = x > 0 ? x*=7 : x+=3 → 둘 다 실행되면 x가 두 번 바뀌어 결과가 틀림
  • 결론: 컴파일러는 성능·안전성·부작용을 다 따져서 필요할 때만 변환

손계산 5 · flag 추적 (슬라이드 Exercise): 각 명령 후 %rax, SF·CF·OF·ZF

명령%raxSFCFOFZF
xorq %rax, %rax0000 0000 0000 00000001
subq $1, %raxFFFF FFFF FFFF FFFF1100
cmpq $2, %raxFFFF FFFF FFFF FFFF1000
setl %alFFFF FFFF FFFF FF011000
movzbl %al, %eax0000 0000 0000 00011000
  • xorq %rax, %rax → 자기 자신과 XOR = 0 → ZF = 1
  • subq $1, %rax → 0 − 1 = −1 = FFFF…FFFF: 아무것도 없는 0에서 빼서 비트가 전부 1 → borrow → CF = 1, 음수 → SF = 1
  • cmpq $2, %rax → −1 − 2 = −3 계산 (rax는 안 바뀜): SF = 1, OF = 0 (범위 안), CF = 0 (unsigned로 FFFF…FFFF ≥ 2라 borrow 없음)
  • setl %al → SF ^ OF = 1 → al = 01 (−1 < 2 맞음), 나머지 바이트는 그대로 → FFFF…FF01
  • movzbl %al, %eax → 상위 비트 전부 0 → rax = 1
  • setl, movzbl은 조건 코드를 바꾸지 않음 → 플래그는 끝까지 SF=1 CF=0 OF=0 ZF=0

6Loop

do-while

  • do-while은 body를 최소 한 번 실행한 뒤 조건 검사, while은 조건부터 검사
  • goto 버전: Loop: body; if (test) goto Loop;
  • 예제 pcount: x의 1 비트 개수 세기 (population count). LSB를 0x1로 마스킹해 result에 누적하고 x를 오른쪽으로 1씩 shift, x가 0이 되면 종료
    movl $0, %eax     # result = 0
.L2:                  # loop:
    movq %rdi, %rdx
    andl $1, %edx     # t = x & 0x1
    addq %rdx, %rax   # result += t
    shrq %rdi         # x >>= 1 (ZF 세팅)
    jne  .L2          # if (x) goto loop
    ret
  • .L2가 goto 버전의 Loop label에 대응 · shrq %rdi가 ZF를 세팅 → jne: x가 0이 아니면 다시 Loop. goto 버전을 거치면 어셈블리 매핑이 아주 깔끔하게 보임 (교재 저자의 설명 방식)

while 변환 1(jump-to-middle, −Og)

    goto Test;
Loop:
    body
Test:
    if (test) goto Loop;
  • 조건을 먼저 검사해야 하므로 처음에 Test로 무조건 점프 → 참이면 Loop로 돌아가 body 실행, 거짓이면 그대로 빠져나감

while 변환 2(do-while conversion, −O1)

    if (!test) goto Done;
Loop:
    body
    if (test) goto Loop;
Done:
  • do-while 앞에 조건 검사(guard)를 하나 붙인 형태 → 처음부터 거짓이면 Done으로 바로 빠짐
  • 왜 −O1은 이 방식인가: jump-to-middle은 x ≠ 0일 때 첫 body 전에 Test로 한 번, Loop로 다시 한 번 → 불필요한 점프 2번. do-while 변환은 guard 통과 후 점프 없이 바로 body로. 점프는 파이프라인을 깨므로 적을수록 좋음 (분기 예측 실패 시 수십 사이클 손해)

for → while → do-while

  • for의 세 부분: init(처음 한 번) · test(body 전 매번) · update(body 끝 매번) → init; while (test) { body; update; }와 완전히 동일
  • 컴파일 순서: for → while → do-while 변환 → goto (어셈블리 구조 그대로)
  • 예제 pcount_for: WSIZE = 8×sizeof(long) = 64, (x >> i) & 0x1로 i번째 비트 확인. −O1에서는 처음 guard가 사라짐. i = 0이고 WSIZE = 64라 첫 검사는 무조건 참 (x = 0이어도 각 비트가 0이라 result가 안 바뀔 뿐 정확성에 문제 없음)

7Switch 문

switch_eg 예제

long switch_eg(long x, long y, long z) {
    long w = 1;
    switch (x) {
    case 1:  w = y*z; break;
    case 2:  w = y/z;        // fall through
    case 3:  w += z;  break;
    case 5:
    case 6:  w -= z;  break;
    default: w = 2;
    }
    return w;
}
  • 여러 case label: case 5, 6이 같은 코드 실행 (특수한 fall through) · fall through: case 2는 break가 없어 case 3까지 실행 · 빠진 case: 4, 그리고 7 이상은 전부 default
  • if-else를 중첩해서 같은 동작을 만들 수 있지만, switch는 jump table로 다르게 처리

jump table 구조

  • 각 case 코드 블록의 시작 위치에 label(Targ0, Targ1 …)을 붙이고 jump table은 그 label들의 주소를 담은 배열 → goto *JTab[x]; 한 번 조회로 바로 점프, 조건을 하나씩 비교할 필요 없음
    .section .rodata
    .align 8
.L4:
    .quad .L8   # x = 0  → default
    .quad .L3   # x = 1
    .quad .L5   # x = 2
    .quad .L9   # x = 3
    .quad .L8   # x = 4  → default (빠진 case)
    .quad .L7   # x = 5
    .quad .L7   # x = 6
  • .section .rodata → 읽기 전용 영역, .L4가 테이블 시작 주소 · .quad → 엔트리 하나가 8바이트 주소 (주소는 64bit)
  • 테이블에 저장된 것은 "L3"라는 문자열이 아니라 그 label의 실제 메모리 주소. 바이너리에서는 gdb x/8xg <테이블 주소>로 확인 가능

direct jump와 indirect jump

  • direct: jmp .L8 → label 위치로 바로 점프
  • indirect: jmp *.L4(,%rdi,8) → 메모리에 저장된 주소를 읽어 그곳으로 점프. *는 pointer 역참조처럼 "이 주소에 들어 있는 값으로 가라"
  • 주소 계산은 D(Rb, Ri, S) 그대로: base 없음, displacement = .L4, index = x, scale = 8 → .L4 + 8x 위치의 8바이트를 읽어 점프, 0 ≤ x ≤ 6일 때만 유효

setup 코드

switch_eg:
    movq %rdx, %rcx       # z를 %rcx로 복사
    cmpq $6, %rdi         # x:6
    ja   .L8              # unsigned로 x > 6 (음수 포함) → default
    jmp  *.L4(,%rdi,8)    # goto *JTab[x]
  • movq %rdx, %rcx: (보충) case 2의 idivq가 %rdx:%rax를 피제수로 쓰고 cqto가 %rdx를 덮어쓰므로 z를 미리 옮겨 둠
  • cmpq $6 + ja: ja는 unsigned 비교라 x가 음수여도 아주 큰 수로 보여 default로 감 → 범위 검사 한 번으로 해결
  • w = 1 초기화가 여기 없음: w를 덮어쓰는 case(1, 2, default)는 초기값 불필요, w에 더하거나 빼는 case(3, 5, 6)만 필요 → 컴파일러가 필요한 case 안에서만 w = 1을 넣음

각 case 블록

.L3:                  # case 1: w = y*z
    movq %rsi, %rax   # ret = y
    imulq %rdx, %rax  # ret *= z
    ret               # break → 함수 끝
  • fall through 처리 (case 2, 3): C로 풀면 case 2는 w = y/z; goto Merge; · case 3은 w = 1; Merge: w += z;
    • .L5 (case 2): y/z 계산 후 jmp .L6(merge)로 case 3의 w += z 부분에 합류. case 2는 w를 덮어쓰므로 w = 1 불필요
    • .L9 (case 3): movl $1, %eax로 w = 1을 여기서 초기화한 뒤 .L6으로 흘러감
  • .L7 (case 5, 6): w = 1 초기화 후 w −= z. 테이블에서 x=5, x=6 엔트리가 둘 다 .L7 · .L8 (default): w = 2

정리와 jump table의 다른 쓰임

C의 for, switch 문법은 사람이 읽기 쉽지만 어셈블리에는 그런 문법이 없음 → 기본 명령어 + 조건 코드 + 점프로 구현. loop은 do-while 또는 jump-to-middle로, 큰 switch는 jump table로, 드문드문한(sparse) switch는 decision tree(if-else 연쇄)로 변환될 수 있음. jump table은 위험한 기법이 아니라 효율적이고 널리 쓰이는 기법. OS의 interrupt handler table(키보드·마우스·디스크 이벤트마다 번호 → handler 주소)도 같은 구조. 새 장치 추가 = 테이블에 엔트리 하나 추가.

8시험 포인트

  • CF는 unsigned overflow(carry/borrow), OF는 signed overflow
  • SF는 결과 MSB, ZF는 결과 0
  • 하드웨어는 CF와 OF를 항상 둘 다 세팅 → signed/unsigned 해석은 사용자 몫
  • leaq는 flag를 바꾸지 않음
  • 뺄셈의 CF = borrow 여부: 실제 carry out이 없으면 CF = 1 (unsigned로 a < b)
  • OF 조건: 덧셈은 같은 부호끼리 더해 부호가 바뀔 때
  • 뺄셈은 다른 부호끼리 빼서 결과 부호가 a와 다를 때
  • cmpq b, a는 (순서 주의), 결과를 저장하지 않음
  • testq b, a는 (결과 저장 안 함), CF·OF는 항상 0, testq %rax, %rax로 0/음수 검사
  • setl = SF^OF (jl도 같음: 가장 작은 음수에서 빼서 overflow가 나도 대소 판정이 맞음), setle = (SF^OF)|ZF, setg = ~(SF^OF)&~ZF, setb = CF, seta = ~CF&~ZF
  • setX는 최하위 1바이트만 씀 → movzbl로 상위를 0으로 만들어야 함
  • 32bit 목적지 명령은 상위 32bit를 자동으로 0으로
  • 같은 비트열이라도 signed/unsigned 비교 결과가 다를 수 있음 (−1 vs 2)
  • 조건 분기는 C 조건의 반대 조건으로 jump
  • −fno-if-conversion은 cmov 대신 분기로 남기라는 옵션
  • cmov는 then/else를 둘 다 계산
  • 비싼 계산, null 역참조, 부작용 있는 식에는 못 씀
  • 분기가 비싼 이유: 파이프라인에 미리 넣은 명령을 버려야 함
  • while 변환: −Og는 jump-to-middle, −O1은 do-while conversion (guard + do-while)
  • for는 init / while(test) { body; update; }로 바꾼 뒤 같은 방식으로 컴파일
  • 처음 guard는 상수 비교면 제거됨
  • jump table: 엔트리 8바이트, jmp *.L4(,%rdi,8) = .L4 + 8x 주소의 값을 읽어 점프
  • cmpq $6 + ja 한 번으로 x > 6과 음수 x를 모두 default로 보냄 (unsigned 비교)
  • 빠진 case 값은 테이블에서 default label을 가리킴
  • 같은 코드의 case는 같은 label을 가리킴
  • fall through는 jmp로 다음 case의 중간(merge)에 합류하는 방식
  • w = 1 같은 초기화는 그 값이 필요한 case 안으로 옮겨질 수 있음

9연습문제

문제 1. 8-bit에서 addb로 을 계산할 때 결과 비트와 CF, ZF, SF, OF를 구하라.
정답 보기
−128 = 10000000, −1 = 11111111
합 = 1 01111111 → 8-bit 결과 01111111 = 127
CF = 1 (MSB에서 carry out) · ZF = 0 · SF = 0
OF = 1 (음수 + 음수 = 양수)
결과결과 127, CF=1 ZF=0 SF=0 OF=1
문제 2. 8-bit에서 cmpb $1, %al, %al = 0x80 (−128)일 때 SF, OF, ZF, CF와 setl, setb의 값을 구하라.
정답 보기
a − b = −128 − 1 = −129 → 범위 밖 → 8-bit 결과 01111111 = 127
SF = 0, ZF = 0 · OF = 1 (a < 0, b > 0인데 결과 > 0) · CF = 0 (unsigned 128 ≥ 1, borrow 없음)
setl = SF^OF = 1 → signed로 −128 < 1 맞음 · setb = CF = 0 → unsigned로 128 < 1 아님
결과SF=0 OF=1 ZF=0 CF=0, setl=1, setb=0
문제 3. testq %rax, %rax 실행 후 %rax = 0x8000000000000000이라면 ZF, SF, CF, OF와 sets, sete의 결과는?
정답 보기
%rax & %rax = %rax 그대로 → MSB = 1, 0 아님
ZF = 0, SF = 1, CF = 0, OF = 0 (test는 항상 clear)
결과sets = 1 (음수), sete = 0
문제 4. %rax = 0x1234567890ABCDEF인 상태에서 cmpq %rax, %rax → sete %al을 실행하면 %rax는? 이어서 movzbl %al, %eax 후에는?
정답 보기
cmp: a − a = 0 → ZF = 1 → sete가 %al = 0x01
sete 후: 상위 7 byte 유지 → %rax = 0x1234567890ABCD01
movzbl 후: %eax = 1, 상위 32 bit도 0 → %rax = 0x0000000000000001
결과0x1234567890ABCD01 → 0x0000000000000001
문제 5. 다음 C 함수를 cmp와 setX, movzbl로 번역하라. (x는 %rdi, y는 %rsi, 반환 %rax) 
int le_u(unsigned long x, unsigned long y) { return x <= y; }
정답 보기
unsigned이므로 CF 기반 조건 사용: x <= y ⇔ ~(x > y) ⇔ ~(~CF & ~ZF) = CF | ZF → setbe (below or equal)
cmpq %rsi, %rdi → x − y로 flag 세팅
setbe %al · movzbl %al, %eax · ret
결과cmpq %rsi,%rdi / setbe %al / movzbl %al,%eax / ret. signed였다면 setle 사용
문제 6. %rdi = −1, %rsi = 1일 때 cmpq %rsi, %rdi 직후 jl, jb, ja 중 점프하는 것은?
정답 보기
−1 − 1 = −2 → SF = 1, OF = 0, unsigned로 FFFF…FFFF ≥ 1이라 CF = 0, ZF = 0
jl: SF ^ OF = 1 → 점프 (signed로 −1 < 1) · jb: CF = 0 → 점프 안 함 · ja: ~CF & ~ZF = 1 → 점프 (unsigned로 FFFF…FFFF > 1)
결과jl과 ja는 점프, jb는 점프 안 함
문제 7. switch_eg(2, 7, 2)와 switch_eg(−1, 7, 2)의 반환값과 거쳐 가는 label은?
정답 보기
x = 2: jmp *.L4(,%rdi,8) → .L5, w = 7/2 = 3, jmp .L6에서 w += 2 → 5
x = −1: cmpq $6 후 ja가 unsigned 비교라 −1 = FFFF…FFFF > 6 → .L8 (default) → 2
결과switch_eg(2,7,2) = 5 (.L5→.L6), switch_eg(−1,7,2) = 2 (.L8)
문제 8. 다음 중 컴파일러가 cmov로 바꾸면 안 되는 것과 이유는?
① val = x > y ? x − y : y − x;  ② val = p ? *p : 0;  ③ val = x > 0 ? x *= 7 : x += 3;
정답 보기
① 괜찮음: 둘 다 가벼운 뺄셈
② 안 됨: p가 null이어도 *p를 계산해 null pointer 역참조
③ 안 됨: 두 식이 다 실행되어 x가 두 번 바뀜 (부작용)
결과② (null 역참조 위험), ③ (부작용). ①은 가능
문제 9. while (x) { result += x & 1; x >>= 1; }를 jump-to-middle과 do-while conversion 두 가지 goto 형태로 쓰고, x가 0이 아닐 때 첫 body 전까지 실제로 일어나는 점프 횟수를 비교하라.
정답 보기
jump-to-middle: goto Test; Loop: body; Test: if (x) goto Loop;
do-while conversion: if (!x) goto Done; Loop: body; if (x) goto Loop; Done:
x ≠ 0일 때 jump-to-middle은 Test로 1번, Loop로 1번 → 2번 · do-while conversion은 guard가 거짓이라 점프 없이 바로 body → 0번
결과jump-to-middle 2번 vs do-while conversion 0번
