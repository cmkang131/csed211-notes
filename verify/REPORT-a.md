## 2. 위젯 요약 (무엇을 가르치나)

- **bit-ops**: w=4/8, A·B 비트 클릭 또는 값 입력(10진/0x/0b, 음수는 2의 보수). 연산 8개(~A, !A, &, |, ^, <<k, >>k 논리, >>k 산술), k 슬라이더 0..w.
  - 결과 칸 위로 입력 비트에서 오는 연결선이 그려집니다. 결과 비트나 입력 비트에 마우스를 올리면 출처와 행선이 빨강으로 강조되고, 아래에 한 줄 설명이 나옵니다.
  - 시프트로 버려지는 비트는 ×로, 채워지는 비트(0 또는 부호 복사)는 빨강으로 표시합니다.
  - 상태 설명에 넣은 내용: ~A = −A−1, ~A와 !A 비교값, &&·||와의 비교, A·2^k mod 2^w와 signed/unsigned 오버플로, ⌊U/2^k⌋, ⌊T/2^k⌋, C의 `/`(0 쪽 절단)과 다를 때의 bias 식 (A+2^k−1)>>k, signed `>>`가 implementation-defined라는 점.
  - **k=w이면 결과 칸을 점선과 ?로 바꾸고 "C에서 UB"라고 명시합니다.** x86-64는 시프트 양을 mod 32로 쓰므로 `x<<32`가 x 그대로 나올 수 있지만 보장되지 않는다는 예도 함께 적었습니다.
- **int-rep**: w 슬라이더 3..8, 비트 토글.
  - U 가중치 행과 T 가중치 행을 나란히 보여 줍니다(MSB 가중치만 −2^{w−1}로 빨강).
  - B2U/B2T 공식에 현재 비트를 대입한 전개식(DOM)을 보여 줍니다.
  - 숫자선에 TMin/−1/0/TMax/UMax 눈금, T 범위와 U 범위 막대, 현재 U 점과 T 점을 그립니다. 부호 비트가 1이면 "B2T = B2U − 2^w" 화살표를 추가합니다.
  - 버튼 +1: 캐리 행, 버려지는 carry out, UMax+1→0, TMax+1→TMin을 표시합니다.
  - 버튼 부호 확장 w→w+4: 복사된 부호 비트를 빨강으로 표시하고, T 값은 보존되지만 U 값은 바뀐다는 점을 보여 줍니다.
  - 버튼 절단 w→4: U는 mod 16, T는 U2T₄ 공식으로 변환합니다(w≤4에서는 비활성).
  - 바로 가기: TMin, TMax, −1(=UMax), 0.
- **float-lab**: binary32 32비트 토글(s/exp/frac 필드 테두리와 숨은 비트 "1."/"0." 칸).
  - 분류, e, E(정규는 e−127, 비정규는 1−127), M(1+f 또는 f), (−1)^s·M·2^E, 정수×2^p, 9자리 근사, **정확한 10진값**, 이 지수의 ulp, 분류별 설명을 표시합니다(gradual underflow, ±0, NaN 등).
  - 프리셋 10개를 제공합니다.
  - 인코더: 10진 문자열을 BigInt 유리수로 파싱한 뒤 RNE로 반올림합니다. 이진 전개(frac 23비트 경계 표시, 분모에 5가 있으면 무한 반복이라는 설명), 두 이웃 float와 중간점의 정확한 10진값, tie·오버플로·언더플로 설명, 정확한 반올림 오차와 상대오차, 위치 비율을 BigInt로 계산한 숫자선을 보여 줍니다.
  - **입력에 대해 `Math.fround(Number(s))`가 다른 답을 내면(double rounding) 그 사실을 표시합니다.**
- **fp-round**: 이진 소수 입력(또는 프리셋 13개), k 슬라이더 0..8.
  - 남는 비트와 버려지는 비트를 구분해 보여 줍니다(빨강, 경계선).
  - 숫자선에 인접한 표현 가능 값 2개, 중간점, 세분 눈금, x를 그립니다.
  - 네 모드(even / zero / +∞ / −∞)의 결과를 화살표와 함께 표시하고, halfway이면 even 행을 빨강으로 강조합니다.
  - 짝수 반올림이 편향이 없는 이유를 한 줄로 설명합니다.
  - 음수에서 toward zero와 toward −∞가 다르면 빨강으로 강조합니다.
  - 프리셋은 교재 2.4.4절 k=2 예 4개, 연습문제 2.50 k=1 4개, 그림 2.37 k=0 3개(1.5, 2.5, −1.5), 음수 2개입니다.

공통 사항은 다음과 같습니다.
- 위젯마다 try/catch로 감싸고, 이벤트 핸들러도 `guard()`로 감쌉니다. 오류가 나면 빨강 한 줄 메시지를 띄웁니다.
- config 값 오류(NaN, 범위 밖, 형식 오류)는 기본값으로 대체하고 "config 경고: …" 한 줄을 띄웁니다.
- `data-config`가 JSON이 아니면 "data-config 가 올바른 JSON 이 아닙니다 (…)" 한 줄을 띄웁니다(아래 4절 참고).

## 4. 독립 코드 리뷰 (별도 서브에이전트, 위젯 레이어 대상) — 지적 4건 모두 반영

1. **[높음] float-lab 인코더 크래시를 고쳤습니다.** 최대 finite < |x| < 2¹²⁸−2¹⁰³ 구간의 입력(예: C가 `%.8g`로 찍는 FLT_MAX 값 `3.4028235e38`)에서 윗이웃이 ∞라서 BigInt 계산이 예외를 냈습니다. 이제 ∞ 이웃은 2¹²⁸로 취급하고 "2¹²⁸ (→+∞)"로 표시합니다. 이 경우를 스크린샷 `float-13`, `float-14`로 확인했습니다. 1차 스크린샷 세트에 이 상태가 없어서 놓쳤던 것입니다.
2. [낮음] UB 문구를 고쳤습니다. 기준을 "w비트 타입에서 k ≥ w"로 바꾸고, 실제 C에서는 char/int8_t가 int로 승격되므로 k ≥ 32가 기준이라는 점을 명시했습니다. 음수의 `<<`와 signed 오버플로가 C에서 UB라는 점도 덧붙였습니다.
3. [낮음] 그림 2.37 프리셋 라벨을 "그림 2.37의 $1.50 을 이진으로: 1.1₂"처럼 바꿨습니다. 원 그림은 10진 달러 금액이기 때문입니다.
4. [낮음] fp-round의 긴 입력이 잘리던 문제를 고쳤습니다. 입력을 24비트로 제한하고 글자 크기를 자동으로 줄입니다. 또 "Σi<₃" 표기를 HTML 아래첨자로 고쳤습니다.

리뷰어가 맞다고 확인한 항목: ~A=−A−1, signed `>>` implementation-defined, bias 식, bias 127, 비정규 E=1−127, 오버플로 경계, ±0/NaN 설명, 9자리 왕복, 음수에서의 방향 단어(위/아래/0 쪽/바깥쪽), mixedFrac, 2.4.4절과 연습문제 2.50 값(3판 기준), XSS 없음(사용자 문자열은 모두 esc 처리).

## 5. 실제 v6.js API와 과제 설명의 차이

- `boot()`는 `data-config` JSON 파싱에 실패하면 **아무 표시 없이 건너뜁니다**(`if(!cfg)return;`). v6.js는 수정할 수 없어서, v6-extra-a.js가 DOMContentLoaded 뒤 `setTimeout 0`에 자체 보조 부트를 돌립니다. 이 보조 부트는 마운트되지 않은 우리 위젯을 찾아 JSON 오류 한 줄을 띄우고, v6.js의 boot가 먼저 끝나 버린 경우(동적 로드 등)에는 직접 마운트합니다. 마운트 여부는 `data-v6xa` 속성으로 구분해 중복 마운트를 막습니다.
- `V6`에는 등록된 위젯을 꺼내 호출하는 API가 없습니다(`widgets`는 비공개). 그래서 보조 부트는 이 파일 안의 `MOUNT` 표를 씁니다.
- v6.js의 boot catch는 영어 "widget error"만 띄웁니다. 우리 위젯은 내부에서 먼저 잡아 한국어 메시지를 띄우므로 이 경로에 도달하지 않습니다.
- `V6.canvas(el,h)`는 720×h 비트맵을 만듭니다. 우리 위젯은 이를 받은 뒤 비트맵만 1440×2h로 키우고 `setTransform(2,…)`로 논리 좌표 720×h를 유지합니다(레티나 선명도 목적, CSS 크기와 비율은 같음).
- 참고(우리 위젯과 무관): v6.js 주석의 slider-plot 예 `"a*x^2+b*x"`는 `makeFn`이 JS 식을 그대로 쓰므로 `^`가 XOR입니다. 과제 설명대로 `^`를 쓰면 안 됩니다.
- 그 밖의 헬퍼(`register`, `title`, `axes`, `makeFn`, 색 상수)는 과제 설명과 같습니다. `axes`와 `makeFn`은 이번 위젯에서 쓰지 않았습니다.

## 6. 한계 · 불확실한 부분 (재확인 권장)

1. **교재 번호**: "연습문제 2.50"과 "그림 2.37"은 CS:APP **3판** 번호입니다. 제 기억과 리뷰어의 확인이 일치했지만, 둘 다 원문을 대조하지는 않았습니다. 수업 교재 판이 다르면 프리셋 라벨만 고치면 됩니다.
2. **폰트**: 이 VM에는 Noto Sans KR이 없어 스크린샷은 Noto Sans CJK로 렌더됐습니다. `.v6-state`는 v6.css에서 `'Noto Sans KR',monospace`라서, 폰트가 없는 환경에서는 한글이 monospace 대체 글꼴로 넓게 보입니다(스크린샷에서 그렇게 보임). 실제 사이트(Google Fonts 로드)에서는 다시 봐야 합니다. demo-a.html은 외부 CDN 금지 때문에 웹폰트를 로드하지 않습니다.
3. **데스크톱 우선**: 캔버스 논리 폭 720 고정입니다. 좁은 화면(모바일)에서는 축소돼 글자가 작아집니다. 880px 뷰포트에서만 촬영했습니다.
4. **마우스 호버**: 터치 기기에서는 hover 하이라이트가 동작하지 않습니다(클릭 토글은 동작). 스크린샷의 hover 상태는 합성 mousemove 이벤트로 만들었습니다. 실제 마우스로는 수동 확인하지 않았습니다.
5. **"x86-64에서 x<<32가 x"** 설명은 하드웨어 시프트 명령의 mod 32 동작을 근거로 "나올 수 있다/보장 안 됨"이라고만 썼습니다. 상수 시프트는 컴파일러가 다르게 처리할 수 있습니다.
6. **9자리 근사**는 JS `toPrecision(9)`에 의존합니다(표시용, float→double은 정확). 정확한 값은 모두 BigInt로 계산합니다.
7. **인코더 입력 범위**: 지수 |e| > 100000이면 입력을 거부합니다(BigInt 폭주 방지). `1e99999`는 +∞로 처리됩니다. 16진 float 리터럴(`0x1.8p3`)과 분수 입력은 지원하지 않습니다.
8. **NaN**: 프리셋과 인코더 모두 quiet NaN 0x7FC00000 하나만 씁니다. 부호와 payload는 구분해 설명하지 않습니다.
9. `fp-round`는 입력 비트 24개(정수부+소수부), k ≤ 8까지만 받습니다.
10. 화면 검사는 "가로 넘침 + 눈 확인"입니다. 글자 겹침을 픽셀 단위로 자동 검사하지는 않았습니다.
