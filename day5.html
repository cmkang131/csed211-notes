제어 흐름과 프로세서 상태

왜 control이 필요한가

기본 동작 : 명령어를 읽고 실행한 뒤 %rip를 그 명령어 크기만큼 증가 → 다음 명령어로 순차 진행

  • 소스 코드를 한 줄씩 진행하는 것과 같음

반복문 끝에서 조건이 만족되면 루프 처음으로 되돌아가야 함 → jump

조건에 따라 다른 분기로 가야 함 → 이를 처리하는 것이 control flow

이번 강의 주제 : 조건 코드 → 조건 분기 → 반복문 → switch문

  • C 소스의 if / loop / switch가 기계어 수준에서 어떻게 구현되는지 보는 것

Processor State (x86-64, 일부)

%rax, %rbx, … %r15 : 범용 레지스터, 임시 데이터 저장

%rsp : runtime stack의 top 위치

%rip : instruction pointer, 현재 실행할 코드 위치

CF ZF SF OF : condition codes, 최근 연산(test) 결과의 상태

핵심 : condition code(상태 레지스터)와 %rip가 함께 쓰여서 조건 분기를 구현

  • 연산 결과로 flag가 세팅됨 → 특정 조건이 만족되면 %rip를 특정 위치로 갱신(jump)
  • 루프 안에서의 점프, switch 상태 이동이 모두 이 조합으로 구현됨

Condition Codes(조건 코드)

네 가지 flag

모두 1-bit 레지스터

CF (Carry Flag) : MSB에서 carry out (뺄셈이면 borrow) → 주로 unsigned 해석

ZF (Zero Flag) : 결과가 0 → 공통

SF (Sign Flag) : 결과의 MSB가 1 (signed로 보면 음수) → signed

OF (Overflow Flag) : two's complement overflow → signed

Implicit setting : 산술 명령의 부수효과

산술 명령을 실행할 때마다 flag가 결과 상태를 반영하도록 자동 갱신됨 (side effect로 생각)

예 : addq src, dst ↔ (두 값을 더해 destination에 저장)

CF : MSB에서 carry out 발생 시 set → unsigned overflow

  • 두 값을 더한 결과가 너무 커서 해당 크기(예 : 8-bit) 레지스터에 담을 수 없는 경우

ZF : 이면 set

SF : (signed로 볼 때)이면 set → 결과의 MSB가 1

OF : two's complement overflow 발생 시 set

부호가 다른 두 값(양수 + 음수)을 더하면 overflow는 절대 발생하지 않음

양수 + 양수 → 음수, 또는 음수 + 음수 → 양수가 나오면 부호 관점에서 명백한 overflow

leaq는 flag를 바꾸지 않음 (주소 계산 전용)

해석은 사용자의 몫

하드웨어는 덧셈이 signed인지 unsigned인지 모름 → CF와 OF를 둘 다 계산해서 세팅

  • unsigned 덧셈으로 볼지 signed 덧셈으로 볼지는 사용자(프로그래머·컴파일러)의 해석
  • unsigned로 보면 CF를, signed로 보면 OF를 보면 됨

같은 flag 비트가 상황에 따라 두 가지 의미로 쓰인다는 것을 기억할 것

손계산 1 : 8-bit 덧셈의 flag

8-bit 레지스터 가정, python으로 검증

100 + 50 : 0x96 = −106, CF 0 · ZF 0 · SF 1 · OF 1 → 양+양=음, signed overflow

200 + 100 (unsigned) : 0x2C = 44, CF 1 · ZF 0 · SF 0 · OF 0 → 300 > 255, unsigned overflow

(−100) + (−100) : 0x38 = 56, CF 1 · ZF 0 · SF 0 · OF 1 → 음+음=양, signed overflow

255 + 1 (= −1 + 1) : 0x00 = 0, CF 1 · ZF 1 · SF 0 · OF 0 → unsigned로는 overflow, signed로는 정상

마지막 줄 : 같은 비트 연산인데 unsigned면 overflow(CF=1), signed면 −1 + 1 = 0으로 정상(OF=0) → 해석의 차이

cmp와 test : flag를 명시적으로 세팅

cmp

cmpq src2, src1 : cmpq b, a는 를 계산하되 destination에 저장하지 않음

  • 레지스터는 아무것도 갱신하지 않고, flag 세팅만을 목적으로 뺄셈 수행

피연산자 순서 주의 : 두 번째 operand − 첫 번째 operand

  • cmpq %rsi, %rdi → %rdi − %rsi 를 계산

CF : MSB에서 borrow 발생 시 set → unsigned로

  • 면 뺄셈해도 변화 없음, 면 결과가 음수 → unsigned로 보면 아주 큰 값이 되고 borrow 발생

ZF : , 즉 이면 set

SF : (signed)이면 set → MSB가 1

OF : two's complement overflow 발생 시 set

test

testq src2, src1 : testq b, a는 를 계산하되 destination에 저장하지 않음

  • operand 하나를 mask로 두면 유용

ZF : 이면 set

SF : 이면 set (MSB가 1)

CF, OF : 항상 clear (0)

  • AND 연산에는 carry나 overflow 개념이 없으므로 무관

대표 용법 : testq %rax, %rax → 자기 자신과 AND

  • 결과 = 원래 값 그대로 → ZF=1이면 %rax가 0, SF=1이면 %rax가 음수
  • 값이 0인지 음수인지 한 번에 확인

정리 : 직접 세팅 vs 비교 목적

flag는 산술 연산으로도, cmp/test로도 세팅됨

  • 원리상 flag를 직접 읽어 써도 되지만 프로그래머가 보통 그렇게 하지 않음

대부분 두 값을 비교하는 용도로 사용

  • cmp로 의 부호·overflow·0 여부 확인 → 어느 쪽이 큰지, 같은지
  • test로 0인지 음수인지 확인

setX : flag 읽기

setX 명령

setX dst : condition code 조합에 따라 dst의 최하위 1 byte를 0 또는 1로 세팅

  • 하나 또는 여러 flag를 함께 읽어 true(1) / false(0)를 돌려줌
  • 나머지 7 byte는 바꾸지 않음 → 위쪽 byte에 남아 있던 값이 그대로 남을 수 있음

sete : ZF → Equal / Zero

setne : ~ZF → Not Equal / Not Zero

sets : SF → Negative

setns : ~SF → Nonnegative

setg : ~(SF^OF) & ~ZF → Greater (signed)

setge : ~(SF^OF) → Greater or Equal (signed)

setl : SF^OF → Less (signed)

setle : (SF^OF) | ZF → Less or Equal (signed)

seta : ~CF & ~ZF → Above (unsigned)

setb : CF → Below (unsigned)

쉬운 것 : sete, sets

sete : cmp로 계산 → 같으면 0 → ZF=1 → dst 하위 byte = 1

sets : 산술 연산 결과가 signed로 음수 → SF=1 → dst 하위 byte = 1, 아니면 0

핵심 : setl = SF ^ OF

signed less 판정에 SF와 OF를 함께 봄

  • SF만 보면 안 되는 이유 : overflow가 나면 결과의 부호가 뒤집힘

경우 ① overflow 없음 (OF=0) → 결과 부호가 그대로 맞음 → SF=1이면

경우 ② overflow 발생 (OF=1) → 부호가 뒤집힘 → SF=0인데도 실제로는

  • 예 : 왼쪽이 아주 작은 음수, 오른쪽이 아주 큰 양수

⇒ 두 경우를 합치면

unsigned 비교는 CF로 : (below) ⇔ CF=1

손계산 2 : cmp 4, 2 → setl (수업 예시)

cmpb $4, %al, %al = 2 → , 이므로 setl 결과가 1이어야 함

  • 2 = 00000010, 4 = 00000100
  • 뺄셈 = 덧셈 + two's complement :
  • −4 : 4를 반전 11111011 → +1 → 11111100
  • 00000010 + 11111100 = 11111110 (= −2)

ZF = 0 : 결과 ≠ 0

SF = 1 : MSB = 1

OF = 0 : 양수 − 양수는 overflow 불가

CF = 1 : unsigned 2 < 4 → borrow

setl = SF ^ OF = 1 ^ 0 = 1 → less 조건 만족

setb = CF = 1 → unsigned로도 2 < 4

손계산 3 : overflow가 끼는 비교 (8-bit)

수업에서 "음수끼리" 경우와 "아주 작은 음수 vs 아주 큰 양수" 경우를 직접 해보라고 함 → 숫자를 정해 계산 (python 검증)

cmp b, a 기준, a − b는 8-bit 결과

  • a = −2, b = −1 : 11111111 (−1), SF 1 · OF 0 · ZF 0 · CF 1 → setl 1, −2 < −1 맞음
  • a = −100, b = 100 : 00111000 (+56), SF 0 · OF 1 · ZF 0 · CF 0 → setl 1, −100 < 100 맞음
  • a = 100, b = −100 : 11001000 (−56), SF 1 · OF 1 · ZF 0 · CF 1 → setl 0, 100 > −100 맞음
  • a = 4, b = 4 : 00000000, SF 0 · OF 0 · ZF 1 · CF 0 → setl 0, 같음 → sete = 1

두 번째 줄 : 진짜 값 −200은 8-bit 범위(−128 ~ 127) 밖 → overflow로 +56이 됨 → SF=0이지만 OF=1이 보정 → setl = 1

  • SF만 봤다면 "−100 ≥ 100"이라는 틀린 결론

세 번째 줄 : 진짜 값 +200 → overflow로 −56 → SF=1이지만 OF=1 → setl = 0

Loop(반복문)과의 연결

less 조건이 중요한 이유 : 반복문

  • 매 반복마다 i < count인지 비교 → 만족하면 계속, 아니면 탈출
  • C 코드에서는 신경 쓸 필요 없지만, 밑에서는 cmp로 flag를 세팅하고 그 flag 조합으로 조건 유지 여부를 판단

Byte Register(레지스터)와 movzbl

setX는 byte 레지스터 하나에 씀 : 모든 정수 레지스터는 최하위 byte를 따로 이름으로 참조 가능

64-bit → 하위 byte

  • %rax → %al, %rbx → %bl, %rcx → %cl, %rdx → %dl
  • %rsi → %sil, %rdi → %dil, %rsp → %spl, %rbp → %bpl
  • %r8 ~ %r15 → %r8b ~ %r15b

나머지 byte가 그대로 남으므로 보통 movzbl로 마무리

  • movzbl : byte → 32-bit zero extension
  • 32-bit 명령은 64-bit 레지스터의 상위 32 bit도 0으로 만듦 → %rax 전체가 0 또는 1

손계산 4 : C → assembly, gt

int gt(long x, long y) {
    return x > y;
}
gt:
    cmpq   %rsi, %rdi    # x - y 로 flag 세팅 (x:y 비교)
    setg   %al           # x > y 이면 %al = 1
    movzbl %al, %eax     # 나머지 비트 0 (%rax 전체)
    ret

%rdi = x, %rsi = y, %rax = 반환값

x = 5, y = 3 대입 : 5 − 3 = 2 → ZF=0, SF=0, OF=0 → setg = ~(0^0) & ~0 = 1 → 반환 1

x = 3, y = 3 대입 : ZF=1 → setg = 0 → 반환 0

슬라이드 나머지 (수업에서 아직 안 다룸)

녹취는 setX / setl 설명에서 끝남 ("나머지는 녹화로") → 아래는 슬라이드 내용 요약

손계산 5 : 슬라이드 Exercise (flag 추적)

setl과 movzbl은 flag를 바꾸지 않음, cmp는 %rax를 바꾸지 않음

각 명령 후 %rax, SF · CF · OF · ZF

  • xorq %rax, %rax : 0000 0000 0000 0000, SF 0 · CF 0 · OF 0 · ZF 1
  • subq $1, %rax : FFFF FFFF FFFF FFFF, SF 1 · CF 1 · OF 0 · ZF 0
  • cmpq $2, %rax : FFFF FFFF FFFF FFFF, SF 1 · CF 0 · OF 0 · ZF 0
  • setl %al : FFFF FFFF FFFF FF01, SF 1 · CF 0 · OF 0 · ZF 0
  • movzbl %al, %eax : 0000 0000 0000 0001, SF 1 · CF 0 · OF 0 · ZF 0

subq : 0 − 1 → unsigned borrow → CF=1, 결과 −1 → SF=1

cmpq $2 : −1 − 2 = −3 → SF=1, OF=0 → setl = 1 (signed로 −1 < 2)

  • CF=0 : unsigned로 보면 0xFFFF…FF는 최댓값이라 2보다 큼 → borrow 없음

setl은 %al만 바꿔서 상위 7 byte(FF…)가 남음 → movzbl로 정리해야 1

jX : 조건 Jump(점프)

jX : condition code에 따라 코드의 다른 위치로 점프

  • 조건은 setX와 동일 (jmp만 무조건 점프)
  • je · jne · js · jns · jg · jge · jl · jle · ja · jb

Conditional Branch(조건 분기) : absdiff

gcc -Og -S -fno-if-conversion control.c 로 생성 (cmov 사용을 끈 옛 방식)

long absdiff(long x, long y) {
    long result;
    if (x > y) result = x - y;
    else       result = y - x;
    return result;
}
absdiff:
    cmpq  %rsi, %rdi    # x:y
    jle   .L4           # x <= y 이면 else로
    movq  %rdi, %rax
    subq  %rsi, %rax    # result = x - y
    ret
.L4:                    # x <= y
    movq  %rsi, %rax
    subq  %rdi, %rax    # result = y - x
    ret

C 조건과 반대 조건(x > y → jle)으로 else로 점프

일반 변환 (goto 형태)

ntest = !(test);
if (ntest) goto Else;
val = then_expr;
goto Done;
Else:
val = else_expr;
Done:

Conditional move

cmovX src, dst : if (test) dst = src

  • 양쪽 값을 모두 계산한 뒤 조건에 맞는 것을 고름 → 제어 이동(branch)이 없음
  • branch는 pipeline 흐름을 크게 방해 → GCC가 안전할 때 cmov 사용
absdiff:
    movq   %rdi, %rax
    subq   %rsi, %rax    # result = x - y
    movq   %rsi, %rdx
    subq   %rdi, %rdx    # eval = y - x
    cmpq   %rsi, %rdi    # x:y
    cmovle %rdx, %rax    # x <= y 이면 result = eval
    ret

cmov를 쓰면 안 되는 경우

  • 비싼 계산 : val = test(x) ? hard1(x) : hard2(x); → 둘 다 계산 → 성능 손해
  • 위험한 계산 : val = p ? *p : 0; → p가 NULL이어도 *p 실행 → unsafe
  • 부수효과 : val = x > 0 ? x*=7 : x+=3; → 둘 다 실행되면 x가 틀어짐 → illegal

Loop(반복문) : do-while, while, for

예제 : popcount (x의 1 비트 개수)

do-while → Loop: body; if (test) goto Loop;

    movl  $0, %eax      # result = 0
.L2:                    # loop:
    movq  %rdi, %rdx
    andl  $1, %edx      # t = x & 0x1
    addq  %rdx, %rax    # result += t
    shrq  %rdi          # x >>= 1
    jne   .L2           # if (x) goto loop  (shrq가 ZF 세팅)
    ret

while 변환 ① jump-to-middle (-Og) : goto Test; Loop: body; Test: if (test) goto Loop;

while 변환 ② do-while conversion (-O1) : if (!test) goto Done; Loop: body; if (test) goto Loop; Done:

for : for (init; test; update) body → init; while (test) { body; update; } → 위 방식으로 변환

  • pcount_for처럼 i = 0, i < 64가 처음에 항상 참이면 첫 검사는 최적화로 제거 가능

Switch(스위치(switch))문 : jump table

예 : case 1, 2(fall through), 3, 5·6(공통), default, case 4 없음

switch_eg:
    movq  %rdx, %rcx
    cmpq  $6, %rdi           # x:6
    ja    .L8                # unsigned로 x > 6 (음수 포함) → default
    jmp   *.L4(,%rdi,8)      # goto *JTab[x]
    .section .rodata
    .align 8
.L4:
    .quad .L8    # x = 0  default
    .quad .L3    # x = 1
    .quad .L5    # x = 2
    .quad .L9    # x = 3
    .quad .L8    # x = 4  default (빠진 case)
    .quad .L7    # x = 5
    .quad .L7    # x = 6

indirect jump jmp *.L4(,%rdi,8) : 주소 .L4 + 8x 에서 목적지를 읽어 점프 (주소 = 8 byte)

direct jump jmp .L8 : label이 곧 목적지

fall through (case 2 → 3) : case 2 블록 끝에서 공통 부분(Merge)으로 jmp, case 3은 w = 1로 시작해 Merge로 들어감

바이너리에서는 gdb x /8xg <테이블 주소>로 jump table 내용 확인 가능

정리 : loop은 do-while 또는 jump-to-middle로, 큰 switch는 jump table로, 드문드문한 switch는 decision tree(if-else 연쇄)로 변환될 수 있음

시험 포인트

CF는 unsigned overflow(carry/borrow), OF는 signed overflow, SF는 결과 MSB, ZF는 결과 0

하드웨어는 CF와 OF를 항상 둘 다 세팅 → signed/unsigned 해석은 사용자 몫

leaq는 flag를 바꾸지 않음

cmpq b, a는 (순서 주의), 결과를 저장하지 않음

testq b, a는 , CF·OF는 항상 0, testq %rax, %rax로 0/음수 검사

OF 조건 : 덧셈은 같은 부호끼리 더해 부호가 바뀔 때, 뺄셈은 다른 부호끼리 빼서 결과 부호가 a와 다를 때

setl = SF^OF, setle = (SF^OF)|ZF, setg = ~(SF^OF)&~ZF, setb = CF, seta = ~CF&~ZF

setX는 하위 1 byte만 씀 → movzbl로 상위 비트 정리 (32-bit 명령은 상위 32 bit를 0으로)

같은 비트열이라도 signed/unsigned 비교 결과가 다를 수 있음 (−1 vs 2)

조건 분기는 C 조건의 반대 조건으로 jump

cmov가 부적합한 세 경우 : 비싼 계산, 위험한 계산, 부수효과

switch의 ja는 unsigned 비교라 음수 x도 default로 보냄

연습문제

문제 1

8-bit에서 addb 로 을 계산할 때 결과 비트와 CF, ZF, SF, OF를 구하라.

답

−128 = 10000000, −1 = 11111111

합 = 1 01111111 → 8-bit 결과 01111111 = 127

CF = 1 (MSB에서 carry out)

ZF = 0, SF = 0

OF = 1 (음수 + 음수 = 양수)

문제 2

8-bit에서 cmpb $1, %al, %al = 0x80 (−128)일 때 SF, OF, ZF, CF와 setl, setb의 값을 구하라.

답

a − b = −128 − 1 = −129 → 범위 밖 → 8-bit 결과 01111111 = 127

SF = 0, ZF = 0

OF = 1 (a < 0, b > 0인데 결과 > 0)

CF = 0 (unsigned 128 ≥ 1, borrow 없음)

setl = SF^OF = 1 → signed로 −128 < 1 맞음

setb = CF = 0 → unsigned로 128 < 1 아님

문제 3

testq %rax, %rax 실행 후 %rax = 0x8000000000000000 이라면 ZF, SF, CF, OF와 sets, sete의 결과는?

답

%rax & %rax = %rax 그대로, MSB = 1, 0 아님

ZF = 0, SF = 1, CF = 0, OF = 0 (test는 항상 clear)

sets = 1 (음수), sete = 0

문제 4

%rax = 0x1234567890ABCDEF 인 상태에서 cmpq %rax, %rax → sete %al 을 실행하면 %rax는? 이어서 movzbl %al, %eax 후에는?

답

cmp : a − a = 0 → ZF = 1 → sete가 %al = 0x01

sete 후 : 상위 7 byte 유지 → %rax = 0x1234567890ABCD01

movzbl 후 : %eax = 1, 상위 32 bit도 0 → %rax = 0x0000000000000001
